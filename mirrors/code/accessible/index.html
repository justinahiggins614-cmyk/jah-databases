Section 1 — Description and history

Signature Code is a mirror of the code kind of website: a website whose job is to help a reader write, run, and share code, so a coder can find a snippet, read it, and try a small piece of it. The code kind of website began as printed program listings, then as lists of snippets by language, and then as searchable snippet libraries with a small runner. This mirror follows that same shape: snippet titles, a language for each, the snippet text, and a search over the library.

What this mirror shows is the network's own material. Its sample set is ten Signature sample snippets made for this mirror, with short plain code lines. They are labeled plainly as Signature samples, not as real-world programs or quoted code. Section 2 — Math proof (standard math + metamath)

The mirror's search rule is a deterministic function. For a query Q of words q1 … qn and a snippet S with a title, a language, and code text, the snippet matches when:

match(Q, S) is true when every word of Q appears in S's title, language, or code text

Every matching snippet scores the same: the number of query words, which is the same for all matches of one query. Results are ordered alphabetically by title, so the order is the same every time for the same query.

The calculator rule is a second deterministic function. A sum is read by a small parser with three steps: first it reads a term, then it reads times and divide, then it reads plus and minus, with brackets read first. Worked example: "2 + 3 * 4". Times binds tighter than plus, so 3 * 4 = 12, then 2 + 12 = 14. With brackets, "(2 + 3) * 4" reads the bracket first, 2 + 3 = 5, then 5 * 4 = 20. Words that are not numbers or signs return no result, and nothing the reader types is ever run as code.

Section 3 — Science proof

The science behind this mirror is how code is organized and found: by language and by job, so a coder can read one language at a time, and by a small safe runner, so a sum can be worked out without running strange words as code. The mirror uses the simplest honest form of that idea: a fixed sample library of snippets, each carrying a title, a language, and short code text, with a filter that keeps only the snippets carrying every word asked for, plus a small parser that reads numbers, plus, minus, times, divide, and brackets, in the usual order.

Two measures describe how good such a filter is. Precision is the share of returned snippets that actually match what was asked. Recall is the share of matching snippets in the set that the filter actually returned. This mirror's rule — every query word must appear — favours precision: it returns fewer snippets, but every snippet it returns contains every word you asked for. The parser accepts only digits, a decimal point, the four signs, and brackets; anything else returns no result.
