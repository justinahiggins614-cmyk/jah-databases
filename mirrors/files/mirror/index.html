Section 1

Description and history

Signature Files is a mirror of the files kind of website: a website whose job is to store files and share them, grouped into folders, each file carrying a name, a type, and a size, so a visitor can find a file and fetch a copy. The files kind of website began as shared folders on one machine, then as lists of files with names and sizes that could be opened from anywhere. This mirror follows that same shape: folders, file names, types, and sizes, with a search over the store.

What this mirror stores is the network's own material. Its sample set is ten Signature sample files made for this mirror, about the network's own subjects. They are labeled plainly as Signature sample files, not as real files from real people. The network itself holds 63,826 databases and 12,367,686 records across the 39 websites and the 2,700 per-artifact websites.

Section 2

Math proof (standard math + metamath)

The mirror's filter rule is a deterministic function. For a query Q of words q1 … qn and a file F with a name, a type, and a folder, the file matches when:

match(Q, F) is true when every word of Q appears in F's name, type, or folder

Results are ordered alphabetically by file name, so the order is the same every time for the same query. The total size of the set is the sum of the sizes of its files: 240 + 5120 + 890 + 12 + 45 + 18 + 30 + 1240 + 4980 + 760 = 13335 KB.

Worked example: the query "song" against the sample set. Two files carry the word "song" in their name: "Harvest Song.mp3" (5120 KB, Songs) and "Moon Song.mp3" (4980 KB, Songs). Both match, and "Harvest Song.mp3" lists first because H comes before M in name order. The query "map" matches two files: "River Map.png" and "Trail Map.png", and again the earlier name lists first.

Section 3

Science proof

The science behind this mirror is how files are organized and found: by folder, by name, and by type. A folder groups files that belong together; a name tells what a file holds; a type tells what kind of thing it is, such as a document, an image, an audio file, or a data file. The mirror uses the simplest honest form of that idea: a fixed sample set of files, each carrying a name, a type, a size in kilobytes, and a folder, with a filter that keeps only the files carrying every word asked for.

Two measures describe how good such a filter is. Precision is the share of returned files that actually match what was asked. Recall is the share of matching files in the set that the filter actually returned. This mirror's rule — every query word must appear — favours precision: it returns fewer files, but every file it returns contains every word you asked for. The sizes are the sizes of the sample files; they are not sizes of real files.
