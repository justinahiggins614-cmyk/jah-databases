History

News moved from printed papers to web pages that update through the day, then to live blogs, phone alerts, and video. Portals were once the front door of the web; search and social feeds took much of that role, but the big news organisations still draw tens of millions of visits, and regional news services serve one country or one language.

Description

A news service reports what has happened, as it happens: headlines, full stories, pictures, video, live updates, and explainers that give the background a reader needs to understand a story. Portals, which are front pages that gather news, weather, mail, and search in one place, belong to the same family. A good news service separates what happened from what someone thinks about it, names its sources, and corrects itself when it gets something wrong. The Problem

The problem this record solves is simple to state and easy to get wrong: a person who wants to use the web well needs to know which kinds of service the world actually uses, and which of those the network already provides. Without a directory, the answer is a guess, or a list of names with no order and no proof. With a directory that names the service, counts the sites, gives the ranks, and links the live mirror, the answer can be checked line by line. For news and information, the check is the count and the ranks below, and the mirror link beside them.

The Worked Solution

The method is the same for every record in this pair. First, the ranking was read line by line from the published table and parsed into rank, site, and main use, giving 88 rows. Second, each site was assigned to exactly one of the twenty categories by what the service does, not by who runs it. Third, each category was checked against the twelve live Tier 1 mirrors by exact match, and given a verdict: LINK where a mirror covers the category, EXPAND where a mirror covers only part of it, BUILD where no mirror covers it, and NOT BUILT only for duplicate listings inside the source ranking itself. Fourth, the numbers were recomputed by the demonstration program in this record, twice, and the two digests compared. The teaching ladder runs simple to most complex: what the service is, how it grew, who uses it, where it misleads, and finally the mathematics and the proof.

Limits

Traffic rewards speed and strong feeling, so the loudest story is not always the most important. A headline can promise more than the story delivers, a single source can be wrong, and a story can be framed to favour one side. A ranking of most-visited news sites measures popularity, never accuracy. The ranking measures popularity, never quality, never truth, and never safety. The most-visited service in a category is not the best service, and a service that is missing from the ranking may be missing because it is used in an app, because it serves one country, or because it is new. This record claims only what its sources establish: the ranks, the counts, the verdict, and the mirror link. Everything else is labelled as design-study or as opinion, never as fact.

Science Proof

The science here is the science of measurement. A ranking that counts estimated browser visits is an estimate built from samples and models, not a direct count, and it carries error. Two facts follow. First, the order at the top is more reliable than the exact numbers: a service with far more visits than the next is almost certainly ahead, while two services close together could swap places if the measurement changed. Second, what is left out shapes the result as much as what is counted: phone-app activity is excluded, so services people mostly use in an app are under-counted, and twelve ranks are omitted from this directory, so the list has gaps. A reader who understands these two facts can use the ranking well; a reader who treats it as an exact count will be misled by it. estimated visits = sampled visits scaled by the model; the order is more reliable than the exact numbers

Terms in Plain Words

A database is a named collection of records about one subject, stored so a reader or a program can find, read, and check each record. A record is one entry in a database: a single file with all of its data, written so a person can read it and a program can run it. A slug is the short web-address name of a database, written in lower-case letters with hyphens, for example similarweb-top100-directory. It is the name the database is filed under. The manifest is the master list of every database in the network, kept in data/manifest.json in the jah-databases repository. It records each database's slug, record kind, record count, identifier prefix, and AI name. A slug is free only if it is not already in the manifest. A record kind is the type name of a record, written as the database slug with spaces instead of hyphens. An identifier prefix is the short code stamped at the start of every record identifier in a database, for example JAH-SWTD-. It tells you which database a record belongs to. A generator is a program that creates new records or files on demand from a seed number. The same seed always produces the same output, so a generated record can be checked and reproduced. A seed is the starting number given to a generator. Change the seed and you get a different record; use the same seed and you get the same record again. A generator gate is a check that a generator must pass before its output counts: the emitted record must have the right record kind, the right slug, the database's own identifier prefix, the hard stop of 1,000,000,000, and the right generator prefix. A JCC code (JAH Condensed Code) is a short condensed key that points to one full record: JAHDB/<slug>#<id>, with a jcc_key of k= plus the first 8 characters of the SHA-256 digest of the record. A code is a pointer to the full data, never a replacement for it. An API (Application Programming Interface) is a set of rules that lets one program ask another program for data or work, over the web. MCP (Model Context Protocol) is an open standard that lets an AI program connect to outside tools and data sources through one shared set of rules. AI means artificial intelligence: a program that answers questions, explains, and does work, in plain words. A directory is a guide that lists services by what they do, so a reader can find the right kind of service. A category is one kind of service in a directory, for example search engines or shopping. A mirror is a Signature version of a kind of service, built on the network's own data, with its own name and catalogue. A ranking is a list in order, from most to least, by one measured thing. Estimated browser visits are a count of how many times pages were opened in a web browser, estimated from samples and models, not counted exactly, and not counting activity inside phone apps. The public edition is the edition of a database that records public facts with sources. The Signature edition is the edition made by the network itself, in its own words, with its own designs. A design-study is a design that is specified in full but not yet built or proved; it is never presented as an established fact. Public-harvest means the record was gathered from public records. Signature-generated means the record was made by the network as a Signature design. A teaching ladder is the order in which a database teaches: simple first, then compounded, then most complex. An accessible mirror is a version of a page that can be read without JavaScript, without an account, and by any visiting AI.
