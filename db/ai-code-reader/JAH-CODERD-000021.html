AI Code Reader: Failure Modes and Recovery

JAH-CODERD-000021 — ai code reader record

The AI Code Reader fails safely: this record names the ways it can fail — a missing file, a refused input, an unreachable source, a test that does not pass — and what the program does in each case. A failure never loses data, never writes a half-result, and never pretends to have succeeded. Each failure mode carries its recovery: what the user does, what the program does on its own, and how to tell the failure is fixed. In this public edition the program offers 8 capabilities (listing every function, class, and import in a file (1); a plain-words explanation of each part (2); data-flow tracing from input to output (3); finding where a name is defined and used (4); reading Python, JavaScript, and HTML files (5); warnings for risky patterns it can see (6); an API other programs use to read code (7); a plain-text report readable without JavaScript (8)), 6 interfaces (File picker — choose a file to read, from the workspace or an upload; Code outline — functions, classes, and imports listed with line numbers; Explanation view — each part explained in plain words; Flow view — how data moves from input to output; Reader API — machine-readable code reading for other programs; Plain-text mode — the whole report as readable plain text), and 8 data fields (filename — the file that was read; functions — every function found, with its lines; classes — every class found, with its lines; imports — every import found; explanation — the plain-words explanation of each part; flow — the data flow from input to output; warnings — risky patterns seen, with line numbers; read_date — the date the file was read).
