Boot-Sector Signature Check JAH-MBP-000001

A boot sector is the first 512 bytes a legacy BIOS loads from a bootable disk, and its last two bytes must be the signature 0x55 followed by 0xAA. Without that signature the BIOS refuses the sector as bootable, which makes the signature the smallest possible contract between firmware and operating system code. Everything else in the sector is code and data that the machine runs in real mode, with no operating system underneath it yet.

Writing a boot sector by hand teaches the exact boundary where software meets hardware: the sector is loaded at a fixed address, the processor starts in 16-bit real mode, and the program must fit, with its signature, in 512 bytes. Early boot code typically prints a message through BIOS interrupts, then loads more sectors or switches the processor into a wider mode. The discipline of fitting a working program into 512 bytes is why boot sectors remain a standard first exercise in operating-system study.

The demo builds a 512-byte sector in memory, writes the signature bytes at offsets 510 and 511, and verifies both the size and the signature. It prints the result rather than claiming to boot any machine, because a real boot also depends on firmware, disk geometry, and hardware that a Python simulation does not model.

Protected-Mode GDT Entry JAH-MBP-000002

The Global Descriptor Table is the x86 structure that defines memory segments when the processor runs in protected mode. Each 8-byte entry encodes a segment base address, a limit, an access byte, and flags for granularity and size. Switching to protected mode means building this table, loading its address into the GDTR register, and then far-jumping to code that runs under the new segment rules.

A code-segment entry and a data-segment entry are the minimum useful pair: code needs execute and read permission, data needs read and write permission, and both need a privilege level. Getting any field wrong produces a fault the moment the processor fetches or touches memory under the new rules, which is why descriptor encoding is always verified by decoding the entry back and comparing every field with the intended value.

The demo encodes a flat code segment with base zero and a 4-gigabyte limit, then decodes the entry and prints the recovered base, limit, and access byte. The program models the encoding arithmetic only; it does not switch any real processor mode.

Round-Robin Scheduler JAH-MBP-000003

Round-robin scheduling gives each ready task a fixed time slice in turn, cycling through the queue until every task finishes. It is the simplest fair scheduler: no task can starve another, because every task gets the processor again after at most one full cycle. The cost of fairness is context-switch overhead, which grows as the time slice shrinks, so real systems tune the slice against the workload.

A scheduler keeps a ready queue, a remaining-time count per task, and a clock. On each tick it runs the head task for one slice, subtracts the slice from that task's remaining time, and either retires the task if it finished or moves it to the back of the queue. The completion order depends on burst lengths and slice size, and simulating it by hand is the standard way to learn why slice choice matters.

The demo simulates three tasks with bursts of 5, 3, and 4 ticks under a quantum of 2, printing each slice and the final completion order. The output is a teaching simulation of scheduling policy, not a measurement of any real kernel.

Identity Page Walk JAH-MBP-000004

Paging translates virtual addresses to physical addresses through tables: a page directory points to page tables, and each page-table entry points to a 4-kilobyte page frame plus permission bits. In an identity mapping, virtual address N maps to physical address N, which is the simplest mapping a tiny kernel uses while it is still setting up memory, because code can keep running at the addresses it already uses.

Walking a page table means splitting an address into directory index, table index, and offset, then following the present bits at each level. If any entry is marked not-present, the walk faults instead of translating, and the kernel must decide whether the access was a genuine error or a page that needs loading. Identity mappings avoid that complexity at boot, at the price of giving up memory protection until a fuller mapping is installed.

The demo builds a tiny two-level table where one directory entry points to a table whose entries identity-map the first sixteen pages, then translates three addresses and prints the results. It models table arithmetic, not a real memory-management unit.

Interrupt Vector Dispatch JAH-MBP-000005

An interrupt vector table maps interrupt numbers to handler addresses so the processor knows which code to run when hardware or software raises an interrupt. On x86 real-mode systems the table holds 256 far pointers; protected-mode systems use an Interrupt Descriptor Table with gate descriptors instead. Either way the idea is identical: the number selects a handler, and the handler must save state, serve the event, and return cleanly.

Keyboard input, timer ticks, and disk completion all arrive as interrupts, which is why a tiny kernel installs its handlers before it enables interrupts. A handler that forgets to acknowledge the interrupt controller, or that returns without restoring registers, corrupts the interrupted program. Dispatch tables therefore get tested by invoking each vector in turn and checking that the right handler ran and the machine state survived.

The demo registers handlers for the timer and keyboard vectors plus a default handler, dispatches three interrupt numbers, and prints which handler ran each time. It is a dispatch simulation, not a real interrupt controller.

Keyboard Scan-Code Map JAH-MBP-000006

A PS/2 keyboard sends scan codes, not characters: each key press produces a make code and each release a break code, and the operating system translates those codes into characters using the active layout. The separation matters because the same physical key can mean different characters under different layouts, and because modifier keys like Shift and Control change the meaning of the codes that follow them.

A tiny kernel starts with a small fixed map for the keys it needs: letters, digits, Enter, Backspace, and Space. It tracks shift state separately so that a shifted letter maps to its uppercase form, and it ignores break codes except to clear modifier state. Anything more, including full layout support and international keys, is added later once basic input works.

The demo maps a short scan-code stream, including a Shift press and release, to characters and prints the resulting text. The map is a teaching subset, not a complete keyboard driver.

VGA Text Buffer JAH-MBP-000007

VGA text mode treats video memory as a grid of character cells, classically 80 columns by 25 rows, where each cell holds one character byte and one attribute byte for foreground color, background color, and blink. Writing text means writing those two bytes per cell at the right offset; the display hardware does the rest, which is why text mode was the standard console for early PCs and remains the simplest screen a tiny kernel can drive.

A console driver keeps a cursor row and column, writes characters cell by cell, wraps at the right edge, scrolls the buffer when it runs past the bottom row, and handles newline, carriage return, and backspace as control operations rather than printable characters. Color comes from the attribute byte, so a driver can highlight errors in one color and normal output in another without any graphics code.

The demo writes a greeting into a simulated 80 by 25 cell buffer and prints the first row as characters. It models the buffer layout only; no real display hardware is touched.

FAT12 Directory Entry JAH-MBP-000008

The File Allocation Table filesystem stores directory entries of exactly 32 bytes: an 8-character name, a 3-character extension, an attribute byte, timestamps, a starting cluster, and a file size. FAT12, the variant used on floppy disks, packs cluster numbers 12 bits at a time, which makes its table code fiddly but keeps the on-disk format small enough to parse by hand.

Reading a directory means walking 32-byte entries until an entry whose first byte is zero marks the end, skipping deleted entries and long-name entries, and interpreting the attribute byte to tell files apart from subdirectories, volume labels, and hidden or system entries. A tiny kernel that can parse one entry correctly can list a whole directory, because every entry follows the same layout.

The demo builds one 32-byte entry for a file named HELLO with a TXT extension and a size of 1234 bytes, parses it back, and prints the name, extension, attributes, and size. It parses a constructed entry, not a real disk image.

Syscall Dispatch Table JAH-MBP-000009

A system call is the controlled doorway between user programs and the kernel: the program places a call number and arguments in registers, triggers a trap, and the kernel dispatches through a table of handlers. The table is the kernel's application binary interface in miniature, because every number in it is a promise about what the kernel will do and what it will return. Changing a number breaks programs, so real kernels treat the table as stable public surface.

A minimal ABI needs only a handful of calls to be useful: write output, read input, exit, and report the process identity. Each handler validates its arguments before acting, because a user program that can pass unchecked pointers into the kernel can corrupt kernel memory. Argument checking is therefore part of the handler, not an optional extra.

The demo dispatches four calls by number, including one unknown number that returns an error, and prints each result. It models dispatch logic, not a real trap into kernel mode.

Cooperative Task Switch JAH-MBP-000010

Cooperative multitasking lets each task run until it voluntarily yields, instead of the kernel preempting it on a timer. The switch itself is cheap: save the current task's continuation, pick the next ready task, and resume it. The risk is equally plain: a task that never yields starves everything else, which is why cooperative systems suit small embedded kernels and teaching kernels more than general-purpose ones.

A generator in Python is a natural stand-in for a cooperative task, because yielding suspends the task exactly where it stopped and resuming continues from that point. A tiny scheduler can therefore be written as a loop over generators, pulling one step from each in turn until all are exhausted. The pattern shows the shape of a context switch without any assembly language.

The demo runs two tasks that yield three steps each, interleaved by a round-robin loop, and prints the interleaved steps. It demonstrates cooperative switching logic, not real thread state.

Flat Binary Loader JAH-MBP-000011

A flat binary is a program stored with no headers, relocation tables, or section metadata: the loader copies it to a fixed address and jumps to its first byte. That simplicity is the point for a minimal system, because there is nothing to parse and nothing that can be mis-parsed. The cost is that the program must be built for exactly the address it will run at, and it cannot ask the loader for anything it did not already assume.

A slightly safer variant adds a tiny header: a magic number that proves the file is a program for this loader, an entry offset, and a segment count, followed by segment descriptors giving load addresses and sizes. The loader checks the magic, copies each segment, zeroes the uninitialized region, and only then transfers control. Those checks turn a blind jump into a verified load.

UART Divisor Calculation JAH-MBP-000012

A UART serial port turns bytes into a timed stream of bits, and its baud rate comes from dividing a base clock by a divisor the driver programs into two registers. Getting the divisor right is the whole job for basic serial output: too fast and the receiver samples mid-bit, too slow and the link wastes time, and either way the text on the other end arrives garbled. Serial consoles survive in tiny kernels precisely because the hardware is this simple.

The classic PC divisor formula divides the 1.8432 megahertz base clock by sixteen times the target baud rate, then rounds to the nearest integer. At 9600 baud that gives a divisor of 12; at 115200 baud it gives 1. The driver also sets the line control for eight data bits, no parity, and one stop bit, which is the 8-N-1 configuration nearly every serial console uses.

The demo computes divisors for four standard baud rates and prints the achieved rate and the percentage error for each. It performs divisor arithmetic only; no serial hardware is programmed.

Bump Allocator with Free List JAH-MBP-000013

A kernel needs memory for its own structures before any general allocator exists, and the bump allocator is the standard bootstrap: keep a pointer to the next free byte, hand out aligned blocks by advancing it, and never reclaim anything. It is fast, trivially correct, and useless once memory must be reused, which is exactly why it is a bootstrap and not a final design.

The next step is a free list: freed blocks are linked together and later allocations reuse them before touching fresh memory. A correct free list must split blocks that are larger than requested, coalesce neighbors when a block is freed, and refuse allocations that do not fit anywhere. Each of those rules prevents a distinct class of leak or corruption, and testing them with a small script catches errors that would otherwise surface as mysterious crashes.

The demo allocates three blocks from a 256-byte pool, frees the middle one, allocates a smaller block that reuses it, and prints the pool layout after each step. It simulates allocator bookkeeping, not real kernel memory.

PIT Tick Scheduler JAH-MBP-000014

The programmable interval timer on classic PCs divides a 1.193182 megahertz clock to produce periodic ticks, and a tiny kernel counts those ticks to measure time, schedule delayed work, and preempt tasks. The tick rate is a design choice: faster ticks give finer timing and more preemption points, but each tick costs an interrupt and a handler run, so the rate trades responsiveness against overhead.

A tick scheduler keeps a list of events with target tick counts and runs each event when the counter reaches its target. Sleeping tasks are simply events that wake a task; periodic work is an event that re-arms itself. The whole mechanism is a sorted list plus a counter, which is why it appears in nearly every teaching kernel before any more elaborate timer wheel is introduced.

Multiboot Header Checksum JAH-MBP-000015

The Multiboot specification lets a bootloader load kernels from different authors by defining a header the bootloader can find and trust: a magic number, a flags word, and a checksum word chosen so that magic plus flags plus checksum equals zero modulo two to the thirty-second power. The bootloader scans the first kilobytes of the kernel for the magic, verifies the checksum, and only then reads the flags to learn what the kernel requests.

Flags request services like page-aligned modules, video mode information, and a memory map, so a wrong flags word silently changes what the kernel receives at boot. The checksum catches corrupted or misaligned headers before any of that matters, because a header that fails its checksum is never trusted far enough to misbehave.

The demo builds a header with chosen flags, computes the checksum as the two's-complement of magic plus flags, and verifies that the three words sum to zero modulo two to the thirty-second. It checks header arithmetic, not a real bootloader.
