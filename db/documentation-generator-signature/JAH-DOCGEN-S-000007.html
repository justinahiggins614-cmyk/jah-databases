Documentation Generator: Signature Data Model

JAH-DOCGEN-S-000007 — documentation generator record

The Signature data model extends the public model with Signature fields: the same eight fields, plus the design-study markers that say what is Signature-made, what it was built from, and which generator produced it. Storage is the same small file-based database or JSONL files, so Signature data stays readable without special tools. This record lists the Signature fields and what each one means. In this Signature edition the program offers 8 capabilities (generating full documentation from code and a specification (1); defining every technical term on first use (2); documenting every interface with inputs and outputs (3); listing every test with what it proves (4); a glossary of every term the document uses (5); plain-text documentation readable without JavaScript (6); an API other programs use to generate documentation (7); re-generating docs when the program changes (8)), 6 interfaces (Document form — program name, purpose, interfaces, and tests; Section list — every section the document will hold; Document view — the full document, readable and downloadable; Glossary view — every term defined in plain words; Generator API — machine-readable documentation generation for other programs; Plain-text mode — the document as readable plain text), and 8 data fields (program — the program documented; purpose — its purpose in plain words; interfaces — every interface with inputs and outputs; terms — every technical term defined; tests — every test with what it proves; glossary — the glossary of terms used; generated_date — the date the document was generated; version — the program version documented). This record is number 7 of 24 in the Signature edition of the Documentation Generator database pair, and it specifies the signature data model topic in full — what it is, how it works, what it accepts, what it returns, and how it is tested — so that a builder can build it and a tester can verify it without guessing.
