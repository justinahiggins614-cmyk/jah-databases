Documentation Generator: Signature Overview: What the Signature Edition Adds

JAH-DOCGEN-S-000001 — documentation generator record

The Signature edition of the Documentation Generator is the network's own design of the program: the same job as the public edition, built as original Signature work with its own interface, its own data model, and its own generator. It is a design-study — an original design, presented as a design, never as an established fact or a real public record. This record states what the Signature edition adds, what it deliberately leaves out, and where its designs came from. In this Signature edition the program offers 8 capabilities (generating full documentation from code and a specification (1); defining every technical term on first use (2); documenting every interface with inputs and outputs (3); listing every test with what it proves (4); a glossary of every term the document uses (5); plain-text documentation readable without JavaScript (6); an API other programs use to generate documentation (7); re-generating docs when the program changes (8)), 6 interfaces (Document form — program name, purpose, interfaces, and tests; Section list — every section the document will hold; Document view — the full document, readable and downloadable; Glossary view — every term defined in plain words; Generator API — machine-readable documentation generation for other programs; Plain-text mode — the document as readable plain text), and 8 data fields (program — the program documented; purpose — its purpose in plain words; interfaces — every interface with inputs and outputs; terms — every technical term defined; tests — every test with what it proves; glossary — the glossary of terms used; generated_date — the date the document was generated; version — the program version documented). This record is number 1 of 24 in the Signature edition of the Documentation Generator database pair, and it specifies the signature overview: what the signature edition adds topic in full — what it is, how it works, what it accepts, what it returns, and how it is tested — so that a builder can build it and a tester can verify it without guessing.
