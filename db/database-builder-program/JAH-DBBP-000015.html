Database Builder: Integration with the Other 99 Programs

JAH-DBBP-000015 — database builder program record

The Database Builder works with the other ninety-nine programs in the 100: it offers its own job through its API, and it uses the other programs' APIs where they do a job better — search through the Universal Search Engine, storage through the Database Builder, verification through the Software Testing Center. This record names the programs it depends on, the programs that depend on it, and the order they are built in, so that no program is built before the programs it needs. In this public edition the program offers 8 capabilities (generating a database from a short specification (1); creating records that pass validation on first build (2); writing the manifest entry with a free slug and ID prefix (3); checking the new database against CHECK 2 (4); producing public and Signature editions together (5); reusing the live construction-pattern database (6); an API other programs use to build databases (7); a plain-text build report readable without JavaScript (8)), 6 interfaces (Specification form — subject, record kind, and fields, in plain words; Field editor — add, name, and describe each field; Build button — one action that builds the whole database; Build report — what was built, record counts, validation result; Builder API — machine-readable database building for other programs; Plain-text mode — the build report as readable plain text), and 8 data fields (subject — what the database is about; record_kind — what sort of record it holds; fields — the named fields each record carries; slug — the database's short web-address name; id_prefix — the short code at the start of every record identifier; records — the records built, public and Signature; manifest_entry — the entry written for the manifest; validation — the CHECK 2 result for the new database). This record is number 15 of 24 in the public edition of the Database Builder database pair, and it specifies the integration with the other 99 programs topic in full — what it is, how it works, what it accepts, what it returns, and how it is tested — so that a builder can build it and a tester can verify it without guessing.
