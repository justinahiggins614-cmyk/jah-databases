Specialist AI

JAH Fidelity Validation Guide is the archive-aware specialist for this database. Duties: answer questions from this database's own records, explain methods and limits in plain sentences, and route questions it cannot answer from its own records to the matching related database or to the wider network. It can build an assistant like the user's personal assistant. It answers what it knows from its records and says plainly when a question falls outside them.

Boundless generator

Generator script: gen-simulation-fidelity-validation.js — run node gen-simulation-fidelity-validation.js --n 5. Seeded and deterministic; throttled; duplicate-checked; hard-stops at 1015 or when the topic space is genuinely exhausted. Generated records carry src: "generated" and are never mixed with assistant-built records. Simulation Fidelity and Validation methods and designs only.

Validation engine

Every record passed these checks at build time: schema (all required fields present, ID prefix correct), completeness (full body text, demo code and output present), consistency (edition, source label, ladder rank, and feasibility tier agree), and demo re-execution (each demo program was run again and its stdout matched the stored output byte for byte). Per-record validation results are shown inside each record.

Evidence links

Each record carries an evidence object: methodology sources, supporting records in this database, and a summary of its reproducible calculation. Evidence is rendered inside each record below.

Tool connections

Client-side tools are exposed as window.SimulationFidelityValidationTools with searchRecords(query), generateRecord(seed), validateRecord(id), and runTests(), operating on the loaded records in this page. These are static page tools that run only in the browser on loaded records; no network service is claimed or used.

Testing suite

Build-time results: retrieval pass (16 of 16 records load from the archive index); generation pass (the generator emits deterministic records for --n 5); verification pass (16 of 16 demos re-executed with byte-matching output); failure recovery pass (empty query returns all records; an out-of-range seed is handled; a malformed record line is skipped without breaking the page). Run window.SimulationFidelityValidationTools.runTests() in this page to repeat the client-side checks live.
