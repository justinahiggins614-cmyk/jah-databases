Software Testing Center: Integration with the Other 99 Programs

JAH-STC-000015 — software testing center record

The Software Testing Center works with the other ninety-nine programs in the 100: it offers its own job through its API, and it uses the other programs' APIs where they do a job better — search through the Universal Search Engine, storage through the Database Builder, verification through the Software Testing Center. This record names the programs it depends on, the programs that depend on it, and the order they are built in, so that no program is built before the programs it needs. In this public edition the program offers 8 capabilities (executing a test suite and recording every result (1); comparing actual output with expected output byte for byte (2); running tests in isolation so one failure cannot hide another (3); a permanent test record with date and evidence (4); re-running any suite on demand (5); plain-text test reports readable without JavaScript (6); an API other programs use to run tests (7); a failing test that names the test, the input, and the difference (8)), 6 interfaces (Suite picker — choose the test suite to run; Run button — execute the suite and watch each test report; Result list — every test with pass or fail and its evidence; Failure view — the failing test, its input, expected output, and actual output; Testing API — machine-readable test running for other programs; Plain-text mode — the test report as readable plain text), and 8 data fields (suite — the test suite that ran; tests — the tests in the suite; passed — how many passed; failed — how many failed, with names; evidence — what each test proved; run_date — the date the suite ran; failures — each failure with input, expected, and actual output; verdict — pass only when failures are 0). This record is number 15 of 24 in the public edition of the Software Testing Center database pair, and it specifies the integration with the other 99 programs topic in full — what it is, how it works, what it accepts, what it returns, and how it is tested — so that a builder can build it and a tester can verify it without guessing.
