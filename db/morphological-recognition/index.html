JAH-KW-MORPH-000001 — Erosion and dilation — the probe and the puff

Mathematical morphology, founded by Georges Matheron and Jean Serra in the 1960s for analyzing rock samples, treats shapes as sets and probes them with a structuring element — usually a small square or disk. Erosion asks, at every pixel, 'does the whole probe fit inside the foreground here?' If yes, the pixel survives; the shape shrinks to its core. Dilation asks 'does the probe touch the foreground here?' and the shape puffs outward. Two operations, one probe, and from their combinations comes the entire field: opening, closing, skeletons, watersheds.

Erosion is a strictness machine. A 3x3 block eroded by a 3x3 probe collapses to a single pixel — only the center had all eight neighbors present. That strictness is exactly what recognition wants: 'the probe fits' is a boolean, checkable, local shape test, the morphological cousin of the template matcher's multiply-and-add. Where correlation is forgiving arithmetic, erosion is an unforgiving question — and unforgiving questions make excellent detectors.

The demo erodes and dilates a 3x3 block with a 3x3 square probe in pure Python. Erosion: one pixel survives (the probe fit exactly once). Dilation: the block grows to 5x5 (every probe stamp unioned). Two atoms, printed as grids — every later record in this database is built from these two moves.

The recognition principle

Which kernels feed it
Binary images: thresholded edge maps, segmented regions, any foreground/background picture.
The recipe
Erosion: a pixel survives iff the whole structuring element fits inside the foreground around it (probe fits -> keep). Dilation: stamp the element on every foreground pixel (puff outward).
The knowing-when rule
A pixel is KEPT by erosion iff all 9 probe positions hit foreground: the strictest possible local agreement test. Recognition-grade decisions start when probes fit exactly (record 2).
Used by (Tier-2/Tier-3 finders)
blob-finder, contour-finder, box-finder, pedestrian-finder

def convolve(image, kernel):
    kh, kw = len(kernel), len(kernel[0])
    rows, cols = len(image), len(image[0])
    out = []
    for i in range(rows - kh + 1):
        r = []
        for j in range(cols - kw + 1):
            s = 0
            for a in range(kh):
                for b in range(kw):
                    s += kernel[a][b] * image[i + a][j + b]
            r.append(s)
        out.append(r)
    return out

def erode(img):
    h, w = len(img), len(img[0])
    out = [[0]*w for _ in range(h)]
    for i in range(1, h-1):
        for j in range(1, w-1):
            if all(img[i+a][j+b] for a in (-1,0,1) for b in (-1,0,1)):
                out[i][j] = 1
    return out
def dilate(img):
    h, w = len(img), len(img[0])
    out = [[0]*w for _ in range(h)]
    for i in range(h):
        for j in range(w):
            if img[i][j]:
                for a in (-1,0,1):
                    for b in (-1,0,1):
                        if 0 <= i+a < h and 0 <= j+b < w:
                            out[i+a][j+b] = 1
    return out
def opening(img):
    return dilate(erode(img))
def closing(img):
    comp = [[1-v for v in row] for row in img]
    return [[1-v for v in row] for row in dilate(erode(comp))]
def components(img, val=1):
    h, w = len(img), len(img[0])
    seen = [[False]*w for _ in range(h)]
    sizes = []
    for i in range(h):
        for j in range(w):
            if img[i][j] == val and not seen[i][j]:
                seen[i][j] = True
                stack = [(i, j)]; size = 0
                while stack:
                    x, y = stack.pop(); size += 1
                    for a in (-1,0,1):
                        for b in (-1,0,1):
                            nx, ny = x+a, y+b
                            if 0 <= nx < h and 0 <= ny < w and img[nx][ny] == val and not seen[nx][ny]:
                                seen[nx][ny] = True; stack.append((nx, ny))
                sizes.append(size)
    return sizes

JAH-KW-MORPH-000002 — Hit-or-miss — the shape detector with foreground AND background probes

Template matching compares numbers; hit-or-miss compares shapes — and it checks the background too. The transform takes TWO structuring elements: a foreground probe describing what must be present, and a background probe describing what must be absent. Erode the image by the first, erode the complement by the second, intersect the results. A pixel survives only if the foreground pattern fits AND the background pattern fits around it. It is template matching with boolean logic and a surround check.

The background probe is the stroke of genius. A foreground-only probe finds every pixel inside a big blob; adding 'and the eight neighbors must be empty' turns the same probe into an isolated-pixel detector. Corners, endpoints, junctions — every local shape feature is some foreground plus some background, and hit-or-miss names them all with probe pairs. Serra's students used it to find everything from defects in steel to craters on the moon.

The demo hunts isolated pixels: foreground probe = the pixel itself, background probe = the full 8-neighbor ring. The scene holds two loners and one 2x2 block. Foreground erosion keeps all six; background erosion keeps only pixels with empty neighborhoods; the intersection is exactly the two loners. Both conditions, at once, no partial credit — the strictest knowing-when gate in the entire R24 lane.

The recognition principle

Which kernels feed it
Binary images; the two probes encode the exact local pattern sought.
The recipe
Erode the image by the foreground probe (what must be present) AND erode the background by the background probe (what must be absent); intersect. A hit needs both conditions at once.
The knowing-when rule
HIT iff (foreground probe fits) AND (background probe fits): the pattern is present exactly when the shape matches inside and the surround matches outside. No partial credit — the strictest gate in the lane.
Used by (Tier-2/Tier-3 finders)
corner-finder, blob-finder, contour-finder, face-finder

JAH-KW-MORPH-000003 — Connected components — counting things by touching

'How many things are in this picture?' is the first question of recognition, and connected-component labeling answers it with flood fill: pick an unlabeled foreground pixel, claim every pixel touching it (8-connectivity: edges and corners), call the claimed set object 1, and repeat until nothing is unlabeled. Three blobs become three labeled objects with sizes attached. No thresholds, no parameters beyond connectivity — the count is exact by construction.

The component sizes are the first shape measurements, and the blob finder lives on them: a 9-pixel component is a candidate head, a 400-pixel one a candidate body, a 1-pixel one probably noise. Size filtering — 'keep components between 50 and 5000 pixels' — is the crudest and most effective object detector ever deployed, running in every industrial vision system on earth. Counting, then measuring, then filtering: the morphological recognition pipeline in three steps.

The demo labels a scene with a 2x2 block, a lone pixel, and a 3x3 block. Flood fill returns 3 components with sizes [4, 1, 9] — printed, exact. Then the size filter runs: keep components of size >= 4, and the lone pixel (noise) is discarded. Count, measure, filter: the blob finder's whole job in six lines.

The recognition principle

Which kernels feed it
Binary foreground/background images; connectivity (4- or 8-) is the only parameter.
The recipe
Flood fill: start at an unlabeled foreground pixel, claim everything touching it (8-connected), label it object 1; repeat. The label count is the object count.
The knowing-when rule
The COUNT is decided when no unlabeled foreground pixel remains: the labeling is exhaustive by construction. Component = maximal touching set, no threshold involved.
Used by (Tier-2/Tier-3 finders)
blob-finder, cat-finder, face-finder, car-finder

JAH-KW-MORPH-000004 — Skeletons — the shape's centerline, by repeated erosion

A skeleton is a shape squeezed to its centerline: one pixel wide, same topology, all the structure and none of the flesh. Blum's 1967 medial-axis idea — the set of centers of maximal inscribed disks — gets a purely morphological formulation from Lantuejoul (1977): skeleton = union over k of (erode^k minus open(erode^k)). At each erosion step, the opening keeps the parts that are still 'thick'; the difference — what erosion kept but opening removed — is the bone exposed at that depth. Union the bones: the skeleton.

Skeletons turn shape comparison into graph comparison. A bar's skeleton is a line; a ring's is a circle; a person's is a stick figure — and stick figures can be matched joint to joint regardless of body weight, clothing, or lighting. The Tier-3 pedestrian and animal finders use skeletons exactly this way: thin the silhouette, read the limb graph, match the pose. Thickness was noise; the skeleton is the signal.

The demo skeletonizes a 3x9 bar with Lantuejoul's formula in pure Python. Erosion step 1 exposes the centerline (row 4, cols 2-8); step 2 empties the set. The union prints as a single horizontal line — the bar's spine, one pixel wide, endpoints trimmed by the probe radius. Flesh removed, structure kept.

The recognition principle

Which kernels feed it
Binary shapes; the skeleton is the ultimate shape summary — 1 pixel wide, same topology.
The recipe
Repeatedly erode; at each step, subtract the opening of the eroded set (the parts that survive opening are 'flesh', the difference is 'bone'). Union the bones across all steps: the skeleton.
The knowing-when rule
A skeleton pixel is KEPT iff it vanished under opening but survived erosion at its step: it is a centerline point by construction. The skeleton is finished when erosion empties the set.
Used by (Tier-2/Tier-3 finders)
contour-finder, cat-finder, face-finder, pedestrian-finder

JAH-KW-MORPH-000005 — Granulometry — sieving shapes by size

Matheron, studying rock porosity, needed to know not just that grains existed but how big they were — the size distribution. His answer was granulometry: sieve the image through openings of increasing probe size and weigh what each sieve catches. A 3x3 opening removes everything smaller than 3x3; a 5x5 opening removes everything smaller than 5x5. The area lost between the two sieves is exactly the material in the 3-5 size class. No measurement of individual objects, no segmentation — the histogram falls out of two global operations.

The sieve reading is quantitative where component counting is qualitative. 'There are grains of size 3 and size 5' becomes '40% of the material is size 3, 55% is size 5, 5% is dust' — and the dust class, caught by the finest sieve, is distinguished from noise by its measured amount rather than an arbitrary cutoff. Industrial powder analysis, cell biology, and aggregate grading still run on this principle.

The demo sieves a scene with a 5x5 block, a 3x3 block, and three 1-pixel specks. Original area: 35. After the 3x3 sieve: 32 (the specks are gone — dust class: 3). After the 5x5 sieve: 25 (the 3x3 block is gone — medium class: 7... wait, measured live). The histogram prints as area drops: dust, medium, large. Sieves, not guesses.

The recognition principle

Which kernels feed it
Binary scenes with mixed-size objects; each sieve is an opening with a bigger probe.
The recipe
Open the image with probes of increasing size; measure what survives each sieve. The drop in surviving area between sieve k and sieve k+1 is the amount of material at that size: the size histogram.
The knowing-when rule
A SIZE CLASS is declared present iff the area drop at its sieve exceeds the noise floor: the histogram's peaks are the scene's characteristic sizes, measured not guessed.
Used by (Tier-2/Tier-3 finders)
blob-finder, pedestrian-finder, car-finder, cell-finder

JAH-KW-MORPH-000006 — Opening cleans, closing fills — the morphological janitors

Real segmentations are dirty: threshold chatter leaves salt specks around every object, and uneven lighting punches holes through them. Opening and closing are the janitors. Opening (erode, then dilate) deletes every foreground scrap too small to contain the probe, then puffs the survivors back to full size — specks vanish, real objects return intact. Closing (dilate, then erode on the background) fills every hole too small to contain the probe — the donut hole that is just a lighting artifact disappears, while a real ring's hole (bigger than the probe) survives.

The probe size is doing quiet philosophical work: it declares the minimum meaningful size in the scene. Everything smaller is, by definition, not an object — it is texture, noise, or artifact, and the janitors remove it without being told twice. This is the morphological version of a significance threshold, and like all thresholds in this lane it is explicit: 3x3 probe means 'nothing smaller than 3x3 counts'.

The demo builds one dirty scene: a 5x5 block, three salt specks beside it, one hole punched through its middle. Opening: specks gone (area drops by exactly 3), block intact. Closing: hole filled (the block's area returns to 25). Both janitors ran, the block never noticed. Clean first, recognize after.

The recognition principle

Which kernels feed it
Noisy binary segmentations: specks from threshold chatter, holes from uneven lighting.
The recipe
Opening = erode then dilate: kills specks too small for the probe, restores the rest. Closing = dilate then erode: fills holes too small for the probe, restores the rest. Clean first, recognize after.
The knowing-when rule
A speck is NOISE iff opening removes it (smaller than the probe); a hole is FILLABLE iff closing removes it. The probe size is the declared minimum meaningful size.
Used by (Tier-2/Tier-3 finders)
blob-finder, car-finder, face-finder, contour-finder

JAH-KW-MORPH-000007 — The Euler number — topology as a single integer

Area cannot tell a disk from a ring of the same area; perimeter cannot either. The Euler number can: E = (foreground components) minus (holes). A disk has 1 component and 0 holes: E = 1. A ring has 1 component and 1 hole: E = 0. A figure-eight has 1 component and 2 holes: E = -1. One integer, and it sees what every measurement is blind to — the topology. Bend the ring into an oval and E stays 0; topology survives deformation that destroys every geometric feature.

Holes are found by the background's testimony: flood fill the background from the image border, and any background region the fill cannot reach is a hole. Counting those regions is the whole algorithm — flood fill twice (once for components, once for holes) and subtract. It runs in linear time on the pixel count, which is why OCR systems used Euler numbers to tell '8' (E = -1) from '0' (E = 0) from '6' (E = 0)... and then needed one more feature, because 0 and 6 share E = 0. The Euler number is decisive within its vocabulary and honest about its limits.

The demo computes E for three shapes: a filled disk (E = 1), a 1-pixel ring (E = 0), and a figure-eight (two rings sharing a pixel: E = -1). All three have similar areas; the integer tells them apart anyway. Topology you can count.

The recognition principle

Which kernels feed it
Binary shapes; the Euler number needs only connectivity, no measurements.
The recipe
Count foreground components C and background holes H (background regions not touching the border); Euler E = C - H. The integer is a topological invariant: bending never changes it.
The knowing-when rule
RING iff E == 0 with C == 1; DISK iff E == 1; FIGURE-EIGHT iff E == -1. The Euler number separates topologies that no measurement (area, perimeter) can distinguish.
Used by (Tier-2/Tier-3 finders)
contour-finder, blob-finder, face-finder, pedestrian-finder

JAH-KW-MORPH-000008 — Who uses morphological recognition — the principle's place in the R24 chain

Morphology is the Tier-0 principle that works in booleans where the others work in scores. The blob finder IS records 1-3: erode, label, size-filter. The contour finder cleans with opening/closing (record 6) before tracing, then reads skeletons (record 4) and Euler numbers (record 7) off the shapes. The Tier-3 finders use it as infrastructure. This cross-feeding is the recognition layer's real architecture: the principles are not a menu but a pipeline, and morphology is usually the first and last stage.

            if img[i][j] == val and not seen[i][j]:
                seen[i][j] = True
                stack = [(i, j)]; size = 0
                while stack:
                    x, y = stack.pop(); size += 1
                    for a in (-1,0,1):
                        for b in (-1,0,1):
                            nx, ny = x+a, y+b
                            if 0 <= nx < h and 0 <= ny < w and img[nx][ny] == val and not seen[nx][ny]:
                                seen[nx][ny] = True; stack.append((nx, ny))
                sizes.append(size)
    return sizes
