JAH-TECHS-000001 — The Triplet Gate

Mirrors the public transistor. The public transistor -- the planar MOSFET -- switches current with one gate over one channel, and its standby leakage is set by short-channel electrostatics the single gate cannot fully control. The Signature version departs by stacking three gates in series inside a single transistor footprint, so the channel is pinched from three sides at once.

The Triplet Gate is Manon's original transistor: one source, one drain, and three independently-driven gate fingers stacked vertically in the same footprint a planar device would use. In the on state all three gates drive together for full current; in the off state the middle gate is held at a deeper cut-off bias, forming an electrostatic dam the leakage current must climb over three times.

How it works: leakage in the off state flows by diffusion over the source barrier. Each additional gate in the stack steepens the subthreshold swing back toward the 60 mV/decade thermal limit, because the channel potential is controlled from multiple sides instead of one. The demo models this with the standard subthreshold swing relation: leakage falls exponentially as the swing improves, at the cost of a small series-resistance delay penalty from the stacked gates.

Specifications of the design: single-device footprint (no area penalty versus planar); three stacked gate fingers, 20 nm channel each; subthreshold swing 64 mV/decade versus 85 mV/decade for the short-channel planar baseline; off-state leakage cut by more than an order of magnitude; on-current within 15 percent of the planar device; delay penalty 1.15x.

Why it improves on the original: standby power dominates modern chips. Cutting leakage ~14x per device at the same footprint means a billion-transistor Signature chip idles on a fraction of the planar budget, while the modest speed cost is hidden by running the three gates as one logical gate. JAH-TECHS-000002 — The Layer Weave

Mirrors the public integrated circuit. The public IC routes every signal along a single Manhattan path: one broken via anywhere on a net kills the chip, so yield is a lottery over millions of single points of failure. The Signature version departs by weaving every critical net twice, on two independent layers, so a defect must strike the same net in both weaves to matter.

The Layer Weave is Manon's original chip interconnect: a dual redundant mesh where each logical connection is physically routed as two independent paths on separate metal layers, joined only at redundant via landings. A built-in continuity voter at each receiver picks the intact path; the spare is not wasted -- it carries a delayed copy of the signal, so a transient fault on one weave is masked by the other.

How it works: chip yield follows Poisson statistics over defect-prone vias. With single routing, chip survival is e^(-p*N) for defect probability p over N vias -- essentially zero at modern via counts. With the Weave, a net dies only if both its vias fail, probability p^2, so survival is e^(-p^2*N): the exponent collapses by a factor of p. The demo computes both yields for realistic numbers.

Specifications of the design: dual-layer redundant routing for all critical nets; per-net continuity voter (3-transistor majority element); area overhead 22 percent on interconnect; defect tolerance: survives any single via failure per net; modeled yield at p=1e-3, N=200,000 vias: single-route ~0, Weave ~37 percent.

Why it improves on the original: the public IC throws away whole wafers to via defects. The Weave turns the dominant yield killer into a masked non-event, so the same fab line ships dramatically more working dies -- reliability woven in, not tested in. JAH-TECHS-000004 — The Ledger Table

Mirrors the public relational database. The public relational database updates rows in place: history is overwritten, audits are reconstructed from logs after the fact, and "what did this look like last Tuesday" is a forensic exercise. The Ledger Table is Manon's original database table: each row carries a valid-from and valid-to transaction stamp. An UPDATE closes the old version's validity and appends a new version; a DELETE closes validity without appending. SELECT ... AS OF <time> reads the exact state of the table at that moment, and the full audit trail is simply the table itself -- no separate log to keep in sync.

How it works: versioning is multi-version concurrency control taken to its conclusion. Readers never block writers because every read targets an immutable version; writers never clobber history because writes only append. The demo builds a tiny ledger table for an account balance, applies deposits and corrections, then queries the balance as of three different timestamps and prints the audit trail. Storage cost is modeled as write amplification versus in-place update.

Specifications of the design: append-only versioned rows with valid-from/valid-to stamps; AS OF time-travel queries; audit trail identical to the table (zero separate log); readers never block writers; write amplification ~2.1x versus in-place (each update writes a full new version); history queries are index seeks, not log replays.

The Ledger Table treats history as data -- regulators, debuggers, and curious owners get the whole truth of every row, and no update can ever silently erase what was there before. JAH-TECHS-000005 — The Split-Key Handshake

Mirrors public-key cryptography. Public-key systems typically concentrate trust in one private key on one device: steal the key, own the identity. The Split-Key Handshake is Manon's original key exchange: after an ephemeral public-key agreement, the resulting session key is divided with a 3-of-5 threshold scheme (Shamir-style polynomial sharing over a prime field) and the shares travel by separate routes -- for example, two network paths, a QR code, an audio chirp, and a printed slip. An attacker must compromise three channels, not one, and shares are single-use: the next session re-splits a fresh key.

How it works: the dealer picks a random degree-2 polynomial whose constant term is the secret, evaluated at five points to make five shares. Specifications of the design: 3-of-5 threshold over GF(2^127 - 1); fresh ephemeral polynomial per session (forward secrecy across sessions); shares routed over independent channels; reconstruction by Lagrange interpolation; attacker work factor: 3 channel compromises versus 1 key theft.

Why it improves on the original: the public scheme has a single point of theft. The Split-Key Handshake has no single thing to steal -- the key exists whole only for the instant of use, inside the reconstructing device, and never crosses any wire intact. JAH-TECHS-000006 — The Tile Renderer

Mirrors the public graphics processing unit. The public GPU shades every fragment straight from global memory: the same texture texel is fetched again and again for neighboring pixels, burning memory bandwidth -- the scarcest resource in graphics. The Signature version departs by rendering in small tiles that live in on-chip local memory, so each texel is fetched once per tile and reused by every fragment inside it.

The Tile Renderer is Manon's original graphics processor: the frame is divided into 8x8-pixel tiles, each tile's working set (textures, depth, color) is pulled into fast local memory once, all fragments in the tile are shaded locally, and only the finished tile is written back. A deferred pass discards hidden fragments before shading, so occluded work never costs a fetch at all.

How it works: bandwidth is dominated by repeated texture reads. In immediate mode, F fragments each fetch T texels from global memory: F*T fetches. In the Tile Renderer, each tile fetches its unique texels once into local memory and fragments read locally: roughly U fetches where U is the unique set, far smaller than F*T for coherent scenes. The demo renders a synthetic 64x64 frame with coherent texture access and counts global fetches under both schemes.

Specifications of the design: 8x8 fragment tiles; per-tile local memory holding the tile's texture working set; deferred hidden-surface pass before shading; modeled global texture fetches: immediate mode 16,384, Tile Renderer 1,024 -- a 16x bandwidth cut on coherent content; finished tiles written back once.

Why it improves on the original: the public GPU spends most of its power moving data it already moved. The Tile Renderer moves each texel once and shades locally -- the same image for a fraction of the memory energy, which is what actually limits mobile and embedded graphics.
