Software Testing Center: Signature Export

JAH-STC-S-000013 — software testing center record

Signature export takes Signature designs out as plain text, JSON, or JSONL, with the full content plus the design-study label, the seed, the generator, and the date — so that exported Signature work stays honestly labeled after it leaves. This record specifies the Signature export formats and how an export is verified complete. In this Signature edition the program offers 8 capabilities (executing a test suite and recording every result (1); comparing actual output with expected output byte for byte (2); running tests in isolation so one failure cannot hide another (3); a permanent test record with date and evidence (4); re-running any suite on demand (5); plain-text test reports readable without JavaScript (6); an API other programs use to run tests (7); a failing test that names the test, the input, and the difference (8)), 6 interfaces (Suite picker — choose the test suite to run; Run button — execute the suite and watch each test report; Result list — every test with pass or fail and its evidence; Failure view — the failing test, its input, expected output, and actual output; Testing API — machine-readable test running for other programs; Plain-text mode — the test report as readable plain text), and 8 data fields (suite — the test suite that ran; tests — the tests in the suite; passed — how many passed; failed — how many failed, with names; evidence — what each test proved; run_date — the date the suite ran; failures — each failure with input, expected, and actual output; verdict — pass only when failures are 0). This record is number 13 of 24 in the Signature edition of the Software Testing Center database pair, and it specifies the signature export topic in full — what it is, how it works, what it accepts, what it returns, and how it is tested — so that a builder can build it and a tester can verify it without guessing.
