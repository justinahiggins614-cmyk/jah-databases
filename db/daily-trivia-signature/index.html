A design for daily trivia that asks one question a day, the same question for everyone, with one clear answer, so the whole community plays together. This is a design for a website that has not been built yet, not a real product.

A trivia game with endless questions is a lonely grind: each player answers alone, the questions never end, and there is nothing to talk about afterward, because no two players answered the same question. A daily trivia that asks one question a day, the same question for everyone, turns answering into a shared habit: every morning there is one question, everyone answers it, and afterward everyone can talk about it, because they all answered the same one. The question is the day's conversation, and the answer is the day's lesson, and the habit brings the players back tomorrow.

Worked example, Signature design: the same Monday question is checked first, its source is named, and the answer is explained in plain words after everyone has answered.

Feasibility: buildable-now Single-answer question writing with checking is established practice today; only the design stands in the way.

A design for daily trivia that writes every question with a single clear answer, so no player can fairly argue that another answer was right. This is a design for a website that has not been built yet, not a real product.

A trivia question with two true answers is unfair: a player answers correctly and is marked wrong, the player argues, and the game loses trust, because the question was badly written. A creator that writes every question with a single clear answer, checks the question for other true answers before it is asked, and refuses any question with two true answers, keeps the game fair: the player who knows the answer is marked right, the player who does not is marked wrong, and no one can fairly argue. The single answer is the game's promise, and the check is how it is kept.

Worked example, Signature design: the same Mars question is written answer-first, checked for other true answers, and its source is named beside the answer.

History

Fair trivia questions are an old discipline, from quiz books that were checked for errors to radio quizzes where a wrong question cost the show. The creator checks before asking, so the game stays fair.

Questions written answer-first; a check for other true answers; a refusal for two-answer questions; a plain challenge review.

A field guide index to the twenty-three records in this database: a map of the whole set, ordered simple to compounded to complex, so a reader can find any record by number and by name. This is a design index for a website that has not been built yet, not a real product.

This database holds twenty-three full records about the daily trivia, ordered from simple to compounded to complex, and a reader arriving without a map cannot tell which record to read first, which records belong together, or where the harder designs begin. The field guide index solves that by listing every record by number and by name, in order, with a one-line account of what each record covers and which rung of the ladder it sits on. Without the index, the simple records and the complex records blur together, and a reader who needs the basics may open a complex design first, while a reader who wants the hardest designs may never find them. The index is the map that keeps the ladder readable, and it is the record that turns twenty-three separate designs into one set a reader can walk through from start to finish.

History

Field guide indexes descend from the tables of contents of books and the catalogues of libraries, where a list of what a collection holds came first and the collection itself came second; this index is the same old habit, written for a database of designs.

Proposed solution

List every record by number, in ladder order, with its Signature design noted; Give each record a one-line account of what its Signature version changes; Mark each record simple, compounded, or complex; Point simple readers to records 1 to 8, and advanced readers to records 17 to 23; Keep the index beside the records, never apart from them.

Dependencies

The twenty-three records themselves, listed in order; the ladder ranks simple, compounded, and complex; agreement that an index lists, and never replaces, the records it points to.
