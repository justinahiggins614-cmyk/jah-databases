The Universal Citation Standard is the one citation form used across the whole network, so a citation to a database, a file, a record, a page, or a section all follow the same shape. Every citation names what it points to, where it lives, and which version it refers to, in the same order every time. A reader who learns the form once can read any citation in the network.

The universal standard was designed when citations in different databases began to drift apart, each with its own order and its own abbreviations. The standard fixed one order and one set of fields, and every database adopted it. This record does not state a creation date.

A universal standard works by fixing the fields every citation must carry — the kind of thing cited, its identifier, its location, and its version — and by fixing their order, so a citation can be parsed by a person and by a machine in the same way. A citation missing a required field is incomplete and is not published. Because the form is the same everywhere, a citation written in one database can be followed from any other.

A Database Citation Identifier is the citation that names a whole database: the database's name, its slug, and the version of its index at the time of citation. It lets a reader cite the database as a whole, for example when crediting the source of a whole collection of records. The identifier is stable: the same database keeps the same identifier across versions, with the version field carrying the change.

Database identifiers were designed so that a whole collection could be credited without citing every record in it. The identifier uses the database slug, which never changes, and a version marker, which does. This record does not state a creation date.

A database citation identifier works by combining the database's stable slug with the version of the index that was read, so the citation points to the database as it stood at that version. A reader follows the identifier to the database's index and can then find the version named. If the version named no longer exists, the citation is reported as stale instead of silently pointing at the current version.

A File Citation Identifier is the citation that names one file in a database: the database, the file's path within it, and the version of the file at the time of citation. It lets a reader point at a single file — a full record file, a data file, or a guide — without citing the whole database. The identifier is written in the universal form, so it reads the same way as every other citation.

File identifiers were designed because many claims rest on one file, not on a whole database, and the citation should be as narrow as the claim. The identifier uses the file's path, which is stable, and a version marker for the file's contents. This record does not state a creation date.

A file citation identifier works by pairing the database slug with the file's path and the version of the file that was read, so the citation resolves to exactly that file at exactly that version. The resolver looks the path up in the database's file list and returns the matching version. If the file has moved or the version is gone, the citation is reported as unresolved rather than pointing at a different file.

A Record Citation Identifier is the citation that names one record: the database, the file, and the record's identifier within it. It is the most common citation in the network, because most claims rest on a single record. The identifier is written in the universal form, with the record's identifier as its final field.

The resolver checks that the record exists in the named file and returns it, or reports the citation as broken if it does not. Because the record identifier is unique, the citation can never resolve to the wrong record in the same file.

The Line-Level Citation System lets a citation point at a single line inside a record or a file, for claims that rest on one exact line. The citation carries the record identifier plus a line number, and the line is counted from the start of the record as stored. Line citations are used sparingly, only where the exact line matters.

Line-level citation was designed for the rare claim that turns on a single line — a number, a name, or a date — where a record-level citation would leave doubt. The system counts lines in the stored record, not in the rendered page, so the number is stable. This record does not state a creation date.

A line-level citation works by taking the record citation and adding the line number within the stored record, so the resolver finds the record and then counts to the line. If the record has been edited and the line has moved, the citation is reported as shifted and the reader is shown the current line at that number. The system never silently re-points a line citation at a different line.

A Source URL Resolver turns a citation identifier into a working web address that a reader can open, and turns a web address back into the citation it came from. It knows the address pattern of every database, file, and page in the network, so it can build the address from the identifier alone. If an identifier cannot be turned into an address, the resolver says so instead of guessing one.

The resolver was designed because citations are written as identifiers, while readers open addresses, and the two forms must convert in both directions. The resolver holds the address pattern for each kind of citation in one place. This record does not state a creation date.

A resolver works by splitting a citation identifier into its fields, looking up the address pattern for its kind, and filling the pattern with the field values to produce the address. The reverse direction splits an address into its parts and rebuilds the identifier. An identifier with an unknown kind or a missing field is reported as unresolvable, and the reason is named.
