Meta-Generator Builder: Integration with the Other 99 Programs

JAH-MGB-000015 — meta generator builder record

The Meta-Generator Builder works with the other ninety-nine programs in the 100: it offers its own job through its API, and it uses the other programs' APIs where they do a job better — search through the Universal Search Engine, storage through the Database Builder, verification through the Software Testing Center. This record names the programs it depends on, the programs that depend on it, and the order they are built in, so that no program is built before the programs it needs. In this public edition the program offers 8 capabilities (creating a builder for a generator kind (1); builders that produce seeded, bounded, tested generators (2); the same seed giving the same builder and the same generators (3); a hard stop inherited by every generator built (4); a test for the builder and for each generator it builds (5); registration of every builder and generator (6); an API other programs use to build meta-generators (7); a plain-text build report (8)), 6 interfaces (Meta form — generator kind, in plain words; Builder view — the builder program, readable and downloadable; Test run — run the builder's tests and see the result; Built generators — every generator this builder has made; Meta API — machine-readable meta-generator building for other programs; Plain-text mode — the build report as readable plain text), and 8 data fields (kind — what the built generators will make; builder_code — the builder program's code; generators — the generators the builder has made; hard_stop — the ceiling inherited by every generator; tests — the test result for the builder and its generators; registry — the registration of builder and generators; seed — the starting number; samples — sample generators and their sample outputs). This record is number 15 of 24 in the public edition of the Meta-Generator Builder database pair, and it specifies the integration with the other 99 programs topic in full — what it is, how it works, what it accepts, what it returns, and how it is tested — so that a builder can build it and a tester can verify it without guessing.
