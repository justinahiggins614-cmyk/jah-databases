JAH-KER-000001 — Sobel Gx kernel — the nine numbers and what each one does

The Sobel operator was published by Irwin Sobel and Gary Feldman in 1968, and it is still the first edge detector most students meet. It is nine numbers arranged in a three-by-three square, and you slide that square across a picture one pixel at a time. At every position you multiply each of the nine numbers by the brightness of the pixel underneath it and add the nine products together. Where the picture is flat, the positives and negatives cancel and the answer is zero. Where brightness jumps — a dark wall meeting a bright doorway — the answer spikes, and the picture lights up along its edges.

Look at the shape of the numbers and you can read the design. The left column is all negative, the right column all positive, and the middle column is zero: the kernel is literally computing 'right side minus left side'. The top and bottom rows use weights of 1 while the middle row uses 2, which means the kernel trusts the row it is standing on twice as much as the rows above and below. That extra trust smooths out a little bit of noise while keeping the edge sharp — the whole trick of the Sobel operator in one sentence.

The demo below builds a small test picture — a dark field of brightness 10 on the left and a bright field of 200 on the right — and runs this exact kernel over it in plain Python with no libraries. The response map shows two tall columns of 760 flanking the edge and zeros everywhere else: the kernel fires exactly where the brightness changes and stays silent where it does not.

What each number does

(1,1)
Top-left: -1. Subtracts the brightness of the pixel one up and one left — part of the 'before' side of the comparison.
(1,2)
Top-middle: 0. Ignores the pixel directly above the center, so pure vertical brightness changes do not leak into this horizontal measure.
(1,3)
Top-right: +1. Adds the brightness of the pixel one up and one right — part of the 'after' side of the comparison.
(2,1)
Middle-left: -2. Subtracts the left neighbor with DOUBLE weight. This is the famous middle number: the row you are standing on gets the strongest vote.
(2,2)
Center: 0. The kernel never looks at the center pixel itself — it compares the neighborhood around it.
(2,3)
Middle-right: +2. Adds the right neighbor with double weight, completing the strongest left-vs-right comparison.
(3,1)
Bottom-left: -1. Subtracts the pixel one down and one left, mirroring the top row so diagonal noise cancels out.
(3,2)
Bottom-middle: 0. Ignores the pixel directly below the center, same as the top-middle.
(3,3)
Bottom-right: +1. Adds the pixel one down and one right, mirroring the top-right.

JAH-KER-000002 — Sobel Gy kernel — the nine numbers and what each one does

The Sobel Gy kernel is the Sobel Gx kernel turned on its side — literally the same nine numbers transposed. Where Gx asks 'is the right side brighter than the left side?', Gy asks 'is the bottom brighter than the top?'. In practice you always run both: Gx finds vertical edges like doorframes and Gy finds horizontal edges like tabletops, and the true edge strength at each pixel is the combination of the two, usually the square root of Gx squared plus Gy squared.

The number-by-number story mirrors Gx exactly, rotated ninety degrees. The top row is negative, the bottom row positive, the middle row zero — 'below minus above'. The middle column carries the double weights (-2 above, +2 below), so once again the pixels the kernel is standing between get the strongest vote, and the corner pixels at weight 1 exist to cancel diagonal noise.

The demo builds a horizontal step edge — dark on top, bright below — and runs Gy over it. The response map shows two tall rows of 760 along the boundary and zeros everywhere else, the exact mirror image of the Gx result on a vertical edge. Run the two demos side by side and you can see why edge detection is always a pair: one kernel alone is blind to edges running parallel to it.

What each number does

(1,1)
Top-left: -1. Part of the negative top row — subtracts brightness from above-left.
(1,2)
Top-middle: -2. Subtracts the pixel directly above with double weight — the trusted row's top half.
(1,3)
Top-right: -1. Subtracts brightness from above-right.
(2,1)
Middle-left: 0. Ignores the left neighbor so horizontal changes do not leak in.
(2,2)
Center: 0. Again, the kernel compares the neighborhood, never the center pixel.
(2,3)
Middle-right: 0. Ignores the right neighbor, same reason.
(3,1)
Bottom-left: +1. Adds brightness from below-left — the start of the 'after' side.
(3,2)
Bottom-middle: +2. Adds the pixel directly below with double weight — the trusted row's bottom half.
(3,3)
Bottom-right: +1. Adds brightness from below-right.

JAH-KER-000003 — Prewitt Gx and Gy — the same shape, middle weight 1

Judith M. S. Prewitt published her edge operator in 1970, and it looks almost embarrassingly like Sobel: the same three columns of -1, 0, +1. The only difference is the middle row. Sobel doubles the middle row's vote to 2; Prewitt leaves it at 1, so every row of the kernel counts equally. It is the most democratic of the three classic operators.

What does the missing doubling cost? On the same step edge the Prewitt Gx peaks at 570 where Sobel peaks at 760 — exactly three quarters, because the total row weight drops from 1+2+1=4 to 1+1+1=3. The shape of the response is identical: same edge columns, same zeros in flat regions. The demo runs Prewitt Gx and Gy side by side on vertical and horizontal step edges so you can watch both orientations behave, and prints the peak values for direct comparison with the Sobel records.

Engineers sometimes prefer Prewitt when they want the simplest possible explanation of what the code is doing — every number is -1, 0, or 1, and the kernel is just 'average of the right column minus average of the left column'. Sobel's 2 buys a little extra noise resistance; Prewitt's 1 buys a little extra honesty about how little it smooths. Neither is wrong, which is exactly the point of the middle-number story in the next record.

What each number does

(1,1)
Top-left: -1. Left-side subtraction, top row.
(1,2)
Top-middle: 0. Ignores the pixel above the center.
(1,3)
Top-right: +1. Right-side addition, top row.
(2,1)
Middle-left: -1. Left neighbor subtracted with weight 1 — NOT doubled. This is the whole difference from Sobel.
(2,2)
Center: 0. Never looked at, same as Sobel.
(2,3)
Middle-right: +1. Right neighbor added with weight 1 — the un-doubled middle number.
(3,1)
Bottom-left: -1. Mirrors the top row.
(3,2)
Bottom-middle: 0. Ignores the pixel below the center.
(3,3)
Bottom-right: +1. Mirrors the top-right.

JAH-KER-000004 — Scharr Gx and Gy — middle 3, center weight 10

In 2000, Hanno Scharr and Joachim Weickert looked at Sobel with fresh eyes and asked an uncomfortable question: is 2 actually the best number, or just the number everyone copied? They optimized the kernel for rotational symmetry — a diagonal edge should give the same strength as a horizontal one — and the math answered: the outer rows want weight 3 and the middle row wants weight 10, not 2. That is the Scharr operator, and it is provably better than Sobel at measuring gradient direction.

On a plain vertical step edge the difference looks like pure volume: Scharr Gx peaks at 3040, exactly four times Sobel's 760, because the row weights total 3+10+3=16 instead of 1+2+1=4. Scale the numbers down and the real advantage appears on angled edges, where Scharr's estimate of the edge direction is measurably closer to the truth. The demo runs Scharr Gx and Gy on the same step edges as the earlier records, printing the 3040 peaks so the progression 570 (Prewitt) → 760 (Sobel) → 3040 (Scharr) is visible in one place.

Scharr is the end of the middle-number argument in one sense: it replaces opinion with an optimization criterion. But notice what it does not do — it does not prove Prewitt or Sobel 'wrong'. Each kernel is the right answer to a slightly different question about how much to trust the pixels around the center.

What each number does

(1,1)
Top-left: -3. Left-side subtraction at triple weight, top row.
(1,2)
Top-middle: 0. Ignores the pixel above the center.
(1,3)
Top-right: +3. Right-side addition at triple weight, top row.
(2,1)
Middle-left: -10. The left neighbor subtracted with weight TEN — the strongest single vote in any classic 3x3 kernel.
(2,2)
Center: 0. Still never looked at.
(2,3)
Middle-right: +10. The right neighbor added with weight ten.
(3,1)
Bottom-left: -3. Mirrors the top row.
(3,2)
Bottom-middle: 0. Ignores the pixel below the center.
(3,3)
Bottom-right: +3. Mirrors the top-right.

JAH-KER-000005 — The middle-number story: 1 vs 2 vs 3/10

Here is the whole controversy in nine numbers. Prewitt says the middle row counts once. Sobel says it counts twice. Scharr says the corners count three times and the middle counts ten times. Three respectable operators, each defended by serious people, and none of them can prove the others wrong — because the middle number is not a fact about the world. It is somebody's opinion about how much you ought to trust the row of pixels you happen to be standing on.

Trust cuts both ways, and the demo proves it with two experiments. First, all three kernels run over the same clean step edge: the peaks come out 570, 760, and 3040, in exact proportion to their row-weight totals. Second, all three run over a single bright pixel lost in a uniform field — pure noise, no edge at all. Every kernel fires at the spike, and the stronger the middle number, the louder the false alarm. That is the trade the middle number encodes: trust the center row more and real edges shout louder, but noise shouts louder too.

Sobel's 2 has survived since 1968 because it sits in a sweet spot most pictures are happy with. Prewitt's 1 is the honest minimum. Scharr's 3-and-10 is the optimized answer once you decide rotational symmetry is the thing you care about. Pick your number by picking what you value — the kernel will not pick for you.

What each number does

(1,1)
Reference frame: in all three operators the corner weights are -1 (top-left) and +1 (top-right) — the corners are the agreed-upon part.
(1,2)
All three operators set the top-middle to 0 — nobody disputes ignoring the straight-above pixel.
(1,3)
Corner agreement continues: +1 top-right in Prewitt and Sobel, scaled to +3 in Scharr.
(2,1)
THE MIDDLE NUMBER, left half: -1 in Prewitt, -2 in Sobel, -10 in Scharr. Three respectable answers to 'how much do you trust this row?'
(2,2)
Center: 0 in all three — the one pixel everyone agrees to ignore.
(2,3)
THE MIDDLE NUMBER, right half: +1, +2, +10. The number is somebody's opinion about how much you ought to trust the row of pixels you happen to be standing on.
(3,1)
Bottom row mirrors the top: -1 / -1 / -3.
(3,2)
Bottom-middle: 0 in all three.
(3,3)
Bottom-right: +1 / +1 / +3.

JAH-KER-000006 — Roberts cross operator — the 2x2 diagonal pair

Lawrence Roberts proposed his edge operator in 1963, five years before Sobel — it is the granddaddy of them all. Instead of a 3x3 square it uses two 2x2 kernels: Gx = [[+1, 0], [0, -1]] measures the difference along the main diagonal, and Gy = [[0, +1], [-1, 0]] measures the difference along the anti-diagonal. It is the smallest edge detector that can possibly work, and on clean images it works beautifully.

Smallness is also its weakness. A 2x2 kernel has no room for any smoothing — there is no trusted middle row, no corner averaging, nothing to average noise away. On a noisy picture Roberts fires at every speck, which is why the 3x3 operators replaced it in most real systems. But it never really died: its diagonal sensitivity and tiny footprint still make it useful in hardware and in teaching, where you want the absolute simplest possible demonstration that differencing neighboring pixels finds edges.

The demo builds a diagonal step edge — bright above the main diagonal, dark below it — and runs both Roberts kernels over it, then combines them into a gradient magnitude map with sqrt(Gx^2 + Gy^2). The magnitude map lights up in a clean diagonal band: four numbers, no smoothing, and the edge is still found.

What each number does

(1,1)
Top-left: +1. Takes the upper-left pixel of the diagonal pair.
(1,2)
Top-right: 0. Ignores the off-diagonal pixel above-right.
(2,1)
Bottom-left: 0. Ignores the off-diagonal pixel below-left.
(2,2)
Bottom-right: -1. Subtracts the lower-right pixel — the difference along the main diagonal.
Gx note
The partner kernel Gy = [[0,+1],[-1,0]] does the same along the anti-diagonal. Together they catch edges the 3x3 family sees at an angle.

JAH-KER-000007 — Laplacian 3x3 — the second-derivative edge finder

Sobel, Prewitt, and Scharr are first-derivative operators: they measure the slope of brightness. The Laplacian measures the curvature — the second derivative. Its kernel adds the four straight neighbors and subtracts the center four times, which is exactly 'the average of my surroundings minus me'. On a flat field the answer is zero. On a bright dot the answer is strongly negative. And on a step edge the answer swings from positive on one side to negative on the other — the edge sits precisely where the response crosses zero.

That zero-crossing property, developed into a full theory by David Marr and Ellen Hildreth in 1980, is the Laplacian's claim to fame: it locates edges to sub-pixel precision without any direction estimate. The price is noise. Second derivatives amplify high-frequency junk even more brutally than first derivatives, so in practice the Laplacian is almost always preceded by a gentle Gaussian blur — the famous Laplacian-of-Gaussian, or LoG.

The demo runs the raw 3x3 Laplacian over the standard vertical step edge and over a perfectly flat field. The flat field returns all zeros, proving the kernel sums to zero. The step edge returns a positive lobe (760) on the dark side and a negative lobe (-760) on the bright side — the zero-crossing between them marks the edge to the pixel.

What each number does

(1,1)
Top-left: 0. The diagonal neighbors are ignored — only the four straight neighbors count.
(1,2)
Top-middle: +1. Adds the pixel directly above.
(1,3)
Top-right: 0. Diagonal ignored.
(2,1)
Middle-left: +1. Adds the left neighbor.
(2,2)
Center: -4. Subtracts the center pixel FOUR times — once for each neighbor it is compared against. This is the whole engine: center versus its surroundings.
(2,3)
Middle-right: +1. Adds the right neighbor.
(3,1)
Bottom-left: 0. Diagonal ignored.
(3,2)
Bottom-middle: +1. Adds the pixel directly below.
(3,3)
Bottom-right: 0. Diagonal ignored.

JAH-KER-000008 — Canny edge detector plus the Kirsch compass masks

In 1986 John Canny published the edge detector that, forty years later, is still the default answer to 'how do I find edges well'. And here is the honest fine print: Canny is not a kernel. You cannot write it as nine numbers. It is a pipeline of five stages, each fixing a weakness of the raw gradient: (1) blur the image with a small Gaussian so noise does not spawn false edges; (2) compute the gradient strength and direction with Sobel; (3) thin the thick gradient ridges down to one-pixel lines with non-maximum suppression — keep a pixel only if it is stronger than its neighbors along the gradient direction; (4) apply TWO thresholds, keeping strong edges and marking weak ones as candidates; (5) trace: keep a weak edge only if it connects to a strong one (hysteresis). The result is thin, continuous, single-pixel edges with the noise left behind.

The demo runs all five stages on a small synthetic picture — a bright square on a dark field — in pure Python, and prints the final edge map as # and . characters so you can see the square's outline traced one pixel wide. Nothing is hidden: every stage's code is in the demo source below.

For contrast the record also carries a Kirsch compass mask (Russell Kirsch, 1971). Kirsch took a different philosophical route: instead of one kernel, use eight — one rotated to each compass direction — and take the strongest response. The North mask shown here weights its top row +5 and everything else -3, so it fires hardest on horizontal edges with brightness to the north. The demo runs it on the same square so you can compare a single directional mask against Canny's full pipeline on identical input.

What each number does

(1,1)
Kirsch North, top-left: +5. The entire top row gets +5 — this mask is tuned to fire on edges whose bright side is to the NORTH.
(1,2)
Top-middle: +5. Same north-side addition.
(1,3)
Top-right: +5. Same north-side addition.
(2,1)
Middle-left: -3. The side and south rows get -3.
(2,2)
Center: 0. Never looked at.
(2,3)
Middle-right: -3.
(3,1)
Bottom-left: -3.
(3,2)
Bottom-middle: -3.
(3,3)
Bottom-right: -3.
Canny note
Canny is honestly NOT a single kernel: it is a five-stage pipeline (blur, gradients, non-maximum suppression, double threshold, hysteresis). The demo runs every stage in plain Python.
Kirsch note
Russell Kirsch's 1971 operator uses EIGHT such masks, one per compass direction (N, NE, E, SE, S, SW, W, NW); the edge strength is the maximum over all eight. Only the North mask is shown here.

def convolve(image, kernel):
    kh, kw = len(kernel), len(kernel[0])
    rows, cols = len(image), len(image[0])
    out = []
    for i in range(rows - kh + 1):
        r = []
        for j in range(cols - kw + 1):
            s = 0
            for a in range(kh):
                for b in range(kw):
                    s += kernel[a][b] * image[i + a][j + b]
            r.append(s)
        out.append(r)
    return out
