Science proof

Wikidata is a directed labeled multigraph: items are vertices, statements are labeled edges, and qualifiers and references annotate the edges. Graph theory gives the working rules: reachability (what is connected to Q42), shortest paths (how Q42 connects to another item), and degree (how many statements an item carries). A SPARQL query is a graph pattern match: the query names a small pattern of vertices and edges, and the engine returns every subgraph that matches it. That is why narrow patterns are fast and whole-graph patterns time out. For this aspect (What It Is and Its Scope), the same graph theory rules decide what counts as a correct answer: the pattern must match the model, and the result must be checkable against the source.

Wikidata: every public way in, in one place.

Wikidata can be reached in several ways, and choosing the wrong one wastes time: a bulk question asked through a single-record API, or a single lookup attempted by downloading a multi-gigabyte dump. The access methods are: Web interface at wikidata.org; SPARQL at query.wikidata.org; EntityData JSON per item; the MediaWiki Action API; weekly JSON and RDF dumps at dumps.wikimedia.org; the Linked Data Fragments endpoint for triple-pattern access; and Wikimedia Enterprise (free account, token) for snapshots, on-demand lookups, and realtime streams. This record lays all of them out side by side with the rule for choosing between them, so a reader picks the right method before the first request. The rule is simple: one record, use the API; a narrow question, use the query endpoint; the whole corpus, use the dumps; and a live feed, use the stream if one exists.

Wikidata: the identifier scheme, and how to read an ID.

Every record in Wikidata has an identifier, and the identifier is the only handle that never changes with the record's content. The scheme is: Items are Q followed by a number (Q42). Properties are P followed by a number (P31 = instance of). Lexemes are L followed by a number. The number is assigned in creation order and never reused. The canonical URI is https://www.wikidata.org/entity/Q42 and the JSON record is at /wiki/Special:EntityData/Q42.json. A reader who understands the scheme can read an ID and know what it names, which collection it belongs to, and how to fetch it. A reader who does not will confuse two records with similar names, cite the wrong one, or store a name where an ID belongs and watch the link break when the name changes. The rule is absolute: store the ID, display the name, and never use the name as the key.
