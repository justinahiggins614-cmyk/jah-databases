# Dictionary entries — The Integration Testbed Database

Key terms of this database, defined in plain words.

## testbed

A place where parts are joined and run together as real programs, to prove they work as one thing, not just alone.

## integration

Joining parts together so they work as one thing, and checking the joins, not just the parts.

## test case

One check with a known right answer, which passes or fails on that answer alone.

## fixture

The fixed starting state a test is run from, set up the same way every time, so the test can be repeated.

## sandbox

A fenced-off place to run a program, where it cannot touch the stored archive until its output has been checked.

## pass

The verdict of a test that gave the expected answer, written down with the time it ran.

## fail

The verdict of a test that gave a different answer, written down with the expected answer beside the real one.

## flaky test

A test that passes sometimes and fails sometimes without any change, which is treated as broken until it is steady.

## regression

A step backwards: when a change breaks something that used to work, caught by running the old tests after every change.

## coverage

The share of the whole that the tests actually exercise, counted so that untested parts are known, not guessed.

## verdict

The final word of a test run: pass or fail, with the failures named in full.

## ledger

The testbed's own written record of every run, every test, and every verdict, kept in order.
