DESCRIPTIONS
Valuation works out a property's worth from what similar properties sold for, what the property earns, and what it costs to keep — shown as a range with the reasons, never as a single magic number. The method is written down and applied the same way to every property: recent sales of similar properties, the income the property earns, and the cost of keeping it. The valuer shows their working — the sales they compared, the numbers they used — so anyone can check it. The value is given as a range, because a single number pretends to know more than anyone can know. When the market moves, the valuation is remade, and the old one is kept beside the new one so the change can be seen. The Property Valuation Method stage works through 4 parts: Comparable sales; Income count; Cost count; Value range. Each part is named, tested, and filed, so the work can be checked by a stranger. This record specifies the stage completely: what it is for, how it is done, how it is tested, what it costs in time and attention, and what can go wrong. The specification is written for a builder who has never done this stage before, and for a reviewer who must judge whether it was done properly. Inside the Persistent Digital Property Ecosystem, Property Valuation Method sits between the stages that come before it and the stages that come after it, and it must fit both: what it receives must be in the shape it expects, and what it hands on must be in the shape the next stage expects. Nothing in this record is a claim that the system it specifies is deployed, live, or finished; it is a specification, documented from public knowledge and established practice, and the sources at the end of this record are the public pages it was checked against.

WORKFLOW
Problem: The problem Property Valuation Method solves is simple to state and hard to do well: Working out what a digital property is worth, honestly. Without this stage, the work goes wrong in a particular way. The failure shows up late, when it is expensive to fix, and it shows up as a surprise, because nothing was recorded that would have warned anyone. The stage exists to move the failure earlier, where it is cheap, and to make it visible, where it can be fixed. The problem is not that people are careless; it is that a job with many parts and many hands needs a fixed shape, or the parts drift apart. Property Valuation Method is that fixed shape for this part of the work.
Solution: The worked solution runs in 5 steps, in order. step 1: Compare recent sales of similar properties; step 2: Count the income the property earns; step 3: Count the cost of keeping it; step 4: Show the working for anyone to check; step 5: Give the value as a range with reasons. Each step has a visible result: something written, something checked, or something handed on, so the stage can be stopped and inspected at any point. The steps are done by the person or program named in the record, and each step is checked before the next begins, because a mistake carried forward is a mistake multiplied. The parts of the stage are: Comparable sales; Income count; Cost count; Value range. When a step fails, the worker stops, fixes the failure, and re-runs the step; the stage never skips a failed step and hopes the next one covers it. The whole method is written so that two workers following it would produce the same result, and a reviewer following it could find where a result came from.
Answer: The answer this stage delivers is a finished piece of work that the next stage can use without asking questions: the Property Valuation Method is complete, checked, and filed. The checks that prove it are: The working is shown for anyone to check; The value is a range, not a magic number; Old valuations are kept beside new ones. When those checks pass, the stage is done, and the proof is the record itself — the checks, the dates, and the names. The figures that describe this stage are: comparables_used = 288; ranges_given = 96; single_number_values = 0; valuations = 96. Those numbers are the record's own checkable figures, and the demo in this record recomputes them from the figures alone, so any reader can verify them without trusting the record's word. A stage whose checks pass is a stage the factory will stand behind.
Applies: Property Valuation Method applies wherever the Persistent Digital Property Ecosystem is used: whenever a new specialist, a new routing, a new room, a new building, or a new property must pass through this stage of the work. It applies when the work is done for the first time and when it is done for the hundredth time, because the stage exists to make the hundredth time as careful as the first. It does not apply where the work is a one-off improvisation with no need for checking or record-keeping; there, a lighter method is honest and this stage would be waste. It applies in full wherever the result must be checked by a stranger, because the stage is what makes the work checkable.
