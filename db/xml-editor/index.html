1. Description

An XML editor writes elements and shows the tree they make, side by side: type the elements, press Check, and see the tree. The editor counts the elements, finds broken elements, and fixes them. Everything runs in this browser; no data leaves the page.

Twenty-four full records, ordered simple to working to advanced, each written in human-readable sentences and paragraphs, each carrying a history, a design, a problem, a proposed solution, dependencies, a feasibility label with its reason, a verification path, a science proof, a math proof, a formal statement, an equation, a proof sketch, a runnable demo program whose output is reproduced on the page, and two named specialist AIs.

2. Math proof

Counting the elements gives 6 elements. A root with 3 children: 3 child elements. A well-formed document has 6 opening and 6 closing tags. A tree 3 levels deep: library, shelf and book. Adding 1 element grows the document from 6 elements to 7 elements.

3. Science proof

An XML editor works because a document is elements in order, and each element wraps its words: a root holds 3 children, and a well-formed document has 6 opening and 6 closing tags. A broken element is one that is not closed, and the editor shows it. That is why the editor shows the tags and the tree side by side, so every change can be seen at once.

4. Working demo

Try it: XML editor (tree check)

Type elements, press Check, and see the tree they make. The editor counts the elements and shows broken elements. Numbered tags such as h1 to h6 count exactly like plain tags: the opening and closing patterns both admit digits.
