Open Robotics Datasets is a public record about Shared datasets that let every lab test on the same robot data. Open robotics datasets are collections of sensor readings, images and maps that labs share, so a new algorithm can be tested on the same data as the old ones. The KITTI dataset, for example, gives camera and lidar recordings from a car driving through Karlsruhe, and it is the standard test for self-driving perception. Good datasets are large, labelled and public, so results can be compared fairly and no lab needs to collect the same data twice. Datasets also reveal weaknesses: an algorithm that works on one dataset and fails on another has learned the dataset, not the task. Robot Benchmarking

Fair tests that rank robot algorithms on the same tasks.

Robot Benchmarking is a public record about Fair tests that rank robot algorithms on the same tasks. A benchmark is a fixed task with a fixed score, so different algorithms can be ranked fairly, and robotics benchmarks cover grasping, navigation, manipulation and learning. Benchmarks need a task, a dataset or simulator, and a scoring rule, and the best ones are run by an independent party so no team can tune the test to its own algorithm. The danger of benchmarks is overfitting: teams tune their algorithm to the benchmark task and it fails on the real task, so good benchmarks rotate tasks and hide the test data. Robot benchmarking has improved the field measurably, because a public scoreboard makes progress visible and competition friendly. Reproducibility in Robotics Research

Making sure a published robot result can be repeated by others.

Reproducibility in Robotics Research is a public record about Making sure a published robot result can be repeated by others. Reproducibility means another lab can repeat a published result with the same code, data and hardware, and robotics struggles with it because robots, rooms and lighting all differ. The fixes are sharing code, sharing datasets, using standard simulators, and reporting the exact hardware and settings, so a reader can rebuild the experiment. Some conferences now award badges to papers whose results were reproduced, and some require code with every submission. Reproducibility matters because a result nobody can repeat is a rumour, not a finding, and the field's progress depends on findings that hold up. Robot Simulation Benchmarks

Testing robot algorithms in simulation before trusting them on hardware.

Robot Simulation Benchmarks is a public record about Testing robot algorithms in simulation before trusting them on hardware. Simulation benchmarks test robot algorithms in a virtual world, where the same test can be repeated exactly and a failure costs nothing. Simulators such as Gazebo and PyBullet model physics, sensors and collisions, so an algorithm can be tested on thousands of virtual runs before it touches a real robot. The gap between simulation and reality is the key risk: an algorithm that only works in the simulator is useless, so benchmarks include noise, delays and imperfect sensors. Simulation benchmarks are how new robot learning methods are compared, since real robots are too slow and fragile for thousands of trials. The challenge pushed humanoid robots forward, because the tasks were chosen from real disaster response, such as the Fukushima accident. Teams had to handle falls, dust and poor radio links, and the robots that finished showed that humanoids could work in real disaster sites. The lessons fed into later robots for inspection, decommissioning and hazardous work, where people should not go. The KITTI Vision Dataset is a public record about The driving dataset that became the standard test for robot cars. KITTI is a dataset of camera and lidar recordings from a car driving around Karlsruhe in Germany, and it is the standard test for self-driving car perception. It was collected by the Karlsruhe Institute of Technology and the Toyota Technological Institute at Chicago, and it includes stereo images, lidar point clouds and GPS positions. KITTI provides labelled benchmarks for stereo vision, optical flow, object detection and tracking, so a new method can be scored against every published method. The dataset is small by modern standards, but it remains the reference because its benchmarks are careful and its results are comparable. Learning from Demonstration in Robotics

Teaching robots by showing them how, instead of programming every step.

Learning from Demonstration in Robotics is a public record about Teaching robots by showing them how, instead of programming every step. Learning from demonstration means teaching a robot by showing it the task, so a person performs the motion and the robot learns to repeat it. The robot records the demonstrator's movements and generalises them, so it can repeat the task from a new starting position or with a slightly different object. The method is used for assembly, pouring, wiping and surgery assistance, where writing a program by hand is hard but showing the motion is easy. The risk is copying mistakes: if the demonstrator is clumsy, the robot learns to be clumsy, so demonstrations are checked before they are taught. Shared Autonomy Research

Humans and robots sharing control of one machine.

Shared Autonomy Research is a public record about Humans and robots sharing control of one machine. Shared autonomy means a human and a robot share control of one machine, such as a wheelchair or a robot arm, with the robot helping and the human deciding. The robot assists with the hard parts, such as avoiding obstacles or holding a steady grasp, while the human keeps the goal and the judgement. The research question is how to split the work: too much robot help and the human feels useless; too little and the human is overloaded. Shared autonomy is used in assistive robots, surgery and teleoperation, where full autonomy is not wanted but full manual control is too hard. Robotics Safety Standards

The ISO rules that keep industrial robots from harming people.

Robotics Safety Standards is a public record about The ISO rules that keep industrial robots from harming people. ISO 10218 is the international safety standard for industrial robots, and it sets rules for guarding, stopping distances and safe speeds. The standard requires risk assessment for every robot cell, so the hazards are listed and the guards, sensors and procedures that control them are chosen on purpose. Collaborative robots, called cobots, follow the related standard ISO/TS 15066, which limits the force a robot may apply to a person. Safety standards are written by committees of makers, users and regulators, and they are updated as robots change. Soft Robotics Research

Robots made of rubber and fabric instead of metal and motors.

Soft Robotics Research is a public record about Robots made of rubber and fabric instead of metal and motors. Soft robotics builds robots from flexible materials such as rubber, fabric and gels, so the robot bends and squeezes instead of moving on stiff joints. Soft robots are safe to touch and can handle fruit, organs and fragile objects, because they spread their grip over a soft surface instead of pinching with hard fingers. A soft gripper is often driven by air: pumping air into chambers makes the fingers curl, and releasing the air lets them relax. The research problems are control and sensing: a soft robot changes shape in many ways at once, so modelling it is harder than modelling a stiff arm. Robot Manipulation Datasets and Benchmarks

Shared objects, grasps and scores for robot hands.

Robot Manipulation Datasets and Benchmarks is a public record about Shared objects, grasps and scores for robot hands. Robot manipulation benchmarks test how well a robot hand grasps and moves objects, using shared object sets such as the YCB set, which gives every lab the same cups, boxes and tools to grasp. The YCB object set was published in 2015, and it lets a grasping result in one lab be compared with a result in another, because the objects are identical. Manipulation benchmarks score success rate, time and gentleness, so a hand that crushes the cup fails even if it lifts it. Shared manipulation data is how robot learning for grasping is trained, since a hand that has seen thousands of grasps generalises better than one that has seen ten. Database

Slug
The short web-address name of a database, in lower-case letters with hyphens.

The master list of every database in the network, kept in data/manifest.json.

The type name of a record: the database slug with spaces instead of hyphens.

The short code at the start of every record identifier in a database.
Generator
A program that creates new records on demand from a seed number; the same seed always gives the same record.
Seed
The starting number given to a generator.
Generator gate
A check a generator must pass before its output counts.
JCC code (JAH Condensed Code)
A short key that points to one full record: JAHDB/<slug>#<id>. A pointer, never a replacement for the full data.
API (Application Programming Interface)
Rules that let one program ask another program for data or work, over the web.

An open standard that lets an AI program connect to outside tools and data through one shared set of rules.
AI
