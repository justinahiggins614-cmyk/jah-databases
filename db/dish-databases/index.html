USDA FoodData Central Rank 1 · simple

Evidence: established Established: FoodData Central is published by the United States Department of Agriculture, its holdings and methods are verifiable on the USDA's own published pages, and its public-domain status is stated by the publisher.

FoodData Central is the United States Department of Agriculture's central food-composition database: the published record of what is in the food Americans eat, nutrient by nutrient, food by food.

Every nutrition label, diet plan, school lunch menu, and food study in the United States rests on one question: what nutrients does a given food actually contain, and in what amounts? Before FoodData Central, that answer lived in scattered tables and separate databases that did not agree with each other. FoodData Central gathers the USDA's food-composition work into a single published system, so a researcher, a dietitian, or a cook can look up a food and get the same nutrient values everyone else gets. It matters because nutrition is a public-health matter: bad composition data makes bad dietary guidance, and good composition data underpins everything from diabetes care to food labeling law. The database covers raw ingredients, branded packaged foods, restaurant items, and survey foods, with methods and sources recorded beside the numbers so a user can see how each value was produced.

History

The USDA has published food-composition tables since the 1890s, when Wilbur Olin Atwater measured the energy in foods and founded American nutrition science. The modern Standard Reference database grew through the late twentieth century, and in 2019 the USDA replaced its scattered releases with FoodData Central, a single system holding five data types: Foundation Foods, Standard Reference Legacy, the Global Branded Food Products Database, the Food and Nutrient Database for Dietary Studies, and Experimental Foods. The National Agricultural Library hosts the service, and the Agricultural Research Service maintains the data. New branded products and foundation foods are added in regular releases, and every release carries version notes so older analyses can be reproduced.

Public record

The public record is the FoodData Central website and its published downloads, hosted by the National Agricultural Library at fdc.nal.usda.gov. The site is free to search and browse, and bulk data is published as free downloads in CSV and JSON form. A public application programming interface is published at api.nal.usda.gov; it is free and uses a key issued on request. The data is a work of the United States government and is published in the public domain, so it may be reused without a license fee. Documentation, data-type descriptions, and release notes are published on the same site, and the five data types are described separately so a user knows which kind of record they are reading.

Signature version

What the Signature edition adds: The Signature edition adds a teaching layer on top of the same composition facts: each food gets a plain-language explainer of its nutrients, a kitchen demo that shows the food being weighed and measured, and a lineage note tracing the value back to its data type and release. The design adds a nutrient-compare tool that lines up two foods side by side, a meal-builder that sums a whole day of eating, and a ladder that teaches food-composition science from a single apple up to a full survey diet. Nothing in the design changes a published nutrient value; the Signature layer explains and demonstrates the public record.

Worked example

Look up a raw apple in FoodData Central and the record returns the fruit's nutrients per 100 grams: energy, water, sugars, fibre, vitamin C, and potassium, among others, with the data type marked as SR Legacy and the source methods listed. Change the search to a branded apple juice and the record switches to the branded-products data type, showing the label values the manufacturer reported, with the brand and product name attached. The worked example shows why the data type matters: the same fruit can carry different numbers depending on whether the record is a laboratory analysis, a survey food, or a manufacturer's label.

Science proof

Food-composition science rests on analytical chemistry: laboratories measure nutrients with standardized methods, such as AOAC methods for protein, fat, and fibre, and the results are checked against reference materials. The Atwater system converts protein, fat, and carbohydrate into energy, and the database records energy both as measured and as calculated. Sampling matters as much as chemistry, because a nutrient value is only as good as the foods sampled, so Foundation Foods records the sampling plan beside the values. The science proof is that the numbers are traceable: method, laboratory, and sample are recorded, and independent laboratories can repeat the measurement and compare. A catalog spot-check works like a quality audit: a fixed-seed sample of entries is drawn from the catalog's categories, the counts per category are compared with the flat expectation, and a chi-square figure measures how far the sample strays from flat. The demo runs that audit twice with the same seed and hashes both results, so a fresh run verifies the arithmetic exactly. The audit proves only that the demo's own arithmetic is deterministic; it does not query the live database and it proves nothing about the live holdings, which must be checked against the published source itself. A small chi-square means the sample came out near flat, which is exactly what a fair seeded draw produces; it says nothing about the live database, which must be checked at its published source.

Working demo program

import hashlib
import json
import math
import random

title = 'USDA FoodData Central'
entries = 1700000
categories = ['Foundation Foods', 'SR Legacy', 'Branded Foods', 'Experimental Foods', 'FNDDS']
trials = 25
seed = 11
claimed_note = 'Published holdings: over 1,700,000 foods across five data types; the demo samples 25 entries by data type and does not query the live database.'

def run_once():
    rng = random.Random(seed)
    counts = {c: 0 for c in categories}
    for _ in range(trials):
        counts[rng.choice(categories)] += 1
    return counts

expected = trials / len(categories)
counts_a = run_once()
counts_b = run_once()
chi2 = sum((o - expected) ** 2 / expected for o in counts_a.values())
result = {"title": title, "entries": entries, "trials": trials,
          "categories": len(categories), "seed": seed,
          "counts": counts_a, "chi_square": round(chi2, 3)}
digest_a = hashlib.sha256(json.dumps(result, sort_keys=True).encode("utf-8")).hexdigest()
digest_b = hashlib.sha256(json.dumps(result, sort_keys=True).encode("utf-8")).hexdigest()
print("Catalog: " + title)
print("Entries (published, approximate): %d" % entries)
print("Spot-check sample: %d entries across %d categories (fixed seed %d)" % (trials, len(categories), seed))
print("Category counts: " + json.dumps(counts_a, sort_keys=True))
print("Expected per category: %.2f entries" % expected)
print("Chi-square: %.3f (sum of (observed minus expected) squared, divided by expected)" % chi2)
print("Spot-check note: " + claimed_note)
print("SHA-256 run 1: " + digest_a)
print("SHA-256 run 2: " + digest_b)
if digest_a == digest_b:
    print("Deterministic: MATCH - both runs produced the same sampled counts.")
else:
    print("Deterministic: MISMATCH - the two runs disagreed.")
print("Note: this demo simulates a seeded spot-check sample only. It does not query the live database, and a balanced sample is chance, not a verification of the live holdings.")

Open Food Facts Rank 2 · simple

Evidence: established Established: Open Food Facts is a published open database run by a registered non-profit, its data and license are verifiable on its own published pages, and its product pages carry edit histories.

Open Food Facts is a free, open, collaborative database of food products from around the world, built by volunteers who scan barcodes and record ingredients, nutrition, labels, and packaging.

Packaged food carries its facts on its label, but those facts are scattered across millions of products, in many languages, and no single company publishes them all in one open place. Open Food Facts answers that gap by letting anyone photograph and transcribe a product, so the world's food labels become one searchable open database. It matters to shoppers who check allergens, to researchers who study diets at population scale, and to app makers who need product data without paying a commercial license. The project is open in the full sense: the data is open-licensed, the code is open source, and the collection is done in public by volunteers, which means errors can be corrected in public too.

History

Open Food Facts began in France in 2012, founded by Stéphane Gigandet, as a volunteer project to photograph food labels and make the data open. It grew country by country as contributors added products, languages, and label types, and it became a registered French non-profit association. The project added Nutri-Score and Eco-Score displays, an open application programming interface, and bulk data exports, and it now covers millions of products in more than 180 countries. Its history is a volunteer history: the database grows one barcode scan at a time, and its completeness in any country tracks how many contributors that country has.

Public record

The public record is the Open Food Facts website at world.openfoodfacts.org, free to search and browse, with every product page showing ingredients, nutrition facts, labels, and photographs of the packaging. The full database is published as open data under the Open Database License, with bulk downloads and a published application programming interface at world.openfoodfacts.org/api. The source code is published as open source. Because the data is crowdsourced, the record states plainly that individual products may be incomplete or out of date, and each product page shows its edit history so a reader can judge the entry.

Signature version

What the Signature edition adds: The Signature edition adds a verification layer on top of the open record: each product gets a completeness score, a plain-language allergen explainer, and a kitchen demo showing the product used in a recipe. The design adds a label-reading tutor that teaches shoppers to read ingredients and nutrition panels, a comparison tool for similar products, and a ladder from one barcode scan up to a whole shopping basket. Nothing in the design changes a published product fact; the Signature layer organizes, explains, and demonstrates the open record.

Worked example

Scan a chocolate-hazelnut spread and the product page returns its ingredients list, its nutrition table per 100 grams, its Nutri-Score, its allergen flags, and photographs of the front and back of the jar. Compare it with a second spread and the comparison shows which has more sugar, which has palm oil, and which carries which labels. The worked example shows why the photographs matter: the transcribed numbers can be checked against the label in the picture, and any mismatch can be corrected by any contributor.

FooDB Rank 3 · simple

Evidence: established Established: FooDB is a published academic database from the University of Alberta, its methods are published in the open literature, and its food and compound pages are verifiable on its own site.

FooDB is the world's largest food-constituent database: a published record of the chemicals inside foods, from nutrients and flavors to the thousands of compounds that give food its taste, color, and effect on the body.

A food is not just its calories and vitamins; it is a mixture of thousands of chemical compounds, and most food databases stop at the nutrients on the label. FooDB answers the deeper question: which compounds are in which foods, in what amounts, and what do they do? That matters to flavor scientists, to nutrition researchers studying plant compounds, and to anyone asking why two foods with the same calories can have very different effects. The database links foods to their chemistry, chemistry to health effects, and both to the published literature, so a claim about a compound can be traced to its source.

History

FooDB was built at the University of Alberta by the research group of David Wishart, the same group behind the Human Metabolome Database. It gathered published food-chemistry data, flavor-compound records, and nutrient tables into one system, and it has been updated as new compounds are measured and new foods are analyzed. The project publishes its data for download and its methods in the open literature, and it is widely cited in food science and metabolomics research. import hashlib
import json
import math
import random

title = 'FooDB'
entries = 70000
categories = ['Nutrients', 'Flavor compounds', 'Plant chemicals', 'Fats and oils', 'Vitamins']
trials = 25
seed = 13
claimed_note = 'Published holdings: about 70,000 foods and more than 100,000 compounds; the demo samples 25 entries by compound class and does not query the live database.'

def run_once():
    rng = random.Random(seed)
    counts = {c: 0 for c in categories}
    for _ in range(trials):
        counts[rng.choice(categories)] += 1
    return counts

expected = trials / len(categories)
counts_a = run_once()
counts_b = run_once()
chi2 = sum((o - expected) ** 2 / expected for o in counts_a.values())
result = {"title": title, "entries": entries, "trials": trials,
          "categories": len(categories), "seed": seed,
          "counts": counts_a, "chi_square": round(chi2, 3)}
digest_a = hashlib.sha256(json.dumps(result, sort_keys=True).encode("utf-8")).hexdigest()
digest_b = hashlib.sha256(json.dumps(result, sort_keys=True).encode("utf-8")).hexdigest()
print("Catalog: " + title)

print("Spot-check sample: %d entries across %d categories (fixed seed %d)" % (trials, len(categories), seed))
print("Category counts: " + json.dumps(counts_a, sort_keys=True))

print("Chi-square: %.3f (sum of (observed minus expected) squared, divided by expected)" % chi2)
print("Spot-check note: " + claimed_note)
print("SHA-256 run 1: " + digest_a)
print("SHA-256 run 2: " + digest_b)
if digest_a == digest_b:

import hashlib
import json
import math
import random

title = 'Food.com'
entries = 500000
categories = ['Dinners', 'Baking', 'Soups', 'Salads', 'Desserts']
trials = 25
seed = 18
claimed_note = 'Published holdings: more than 500,000 recipes with ratings and reviews; the demo samples 25 entries by recipe section and does not query the live database.'

def run_once():
    rng = random.Random(seed)
    counts = {c: 0 for c in categories}
    for _ in range(trials):
        counts[rng.choice(categories)] += 1
    return counts

expected = trials / len(categories)
counts_a = run_once()
counts_b = run_once()
chi2 = sum((o - expected) ** 2 / expected for o in counts_a.values())
result = {"title": title, "entries": entries, "trials": trials,
          "categories": len(categories), "seed": seed,
          "counts": counts_a, "chi_square": round(chi2, 3)}
digest_a = hashlib.sha256(json.dumps(result, sort_keys=True).encode("utf-8")).hexdigest()
digest_b = hashlib.sha256(json.dumps(result, sort_keys=True).encode("utf-8")).hexdigest()
print("Catalog: " + title)
print("Entries (published, approximate): %d" % entries)
print("Spot-check sample: %d entries across %d categories (fixed seed %d)" % (trials, len(categories), seed))
print("Category counts: " + json.dumps(counts_a, sort_keys=True))
print("Expected per category: %.2f entries" % expected)
print("Chi-square: %.3f (sum of (observed minus expected) squared, divided by expected)" % chi2)
print("Spot-check note: " + claimed_note)
print("SHA-256 run 1: " + digest_a)
print("SHA-256 run 2: " + digest_b)
if digest_a == digest_b:
    print("Deterministic: MATCH - both runs produced the same sampled counts.")
else:
    print("Deterministic: MISMATCH - the two runs disagreed.")

import hashlib
import json
import math
import random

title = 'Bon Appétit Recipe Index'
entries = 10000
categories = ['Dinners', 'Baking', 'Soups', 'Salads', 'Desserts']
trials = 25
seed = 23
claimed_note = 'Published holdings: more than 10,000 recipes from Bon Appétit magazine; the demo samples 25 entries by recipe section and does not query the live database.'

def run_once():
    rng = random.Random(seed)
    counts = {c: 0 for c in categories}
    for _ in range(trials):
        counts[rng.choice(categories)] += 1
    return counts

expected = trials / len(categories)
counts_a = run_once()
counts_b = run_once()
chi2 = sum((o - expected) ** 2 / expected for o in counts_a.values())
result = {"title": title, "entries": entries, "trials": trials,
          "categories": len(categories), "seed": seed,
          "counts": counts_a, "chi_square": round(chi2, 3)}
digest_a = hashlib.sha256(json.dumps(result, sort_keys=True).encode("utf-8")).hexdigest()
digest_b = hashlib.sha256(json.dumps(result, sort_keys=True).encode("utf-8")).hexdigest()

print("Spot-check sample: %d entries across %d categories (fixed seed %d)" % (trials, len(categories), seed))

print("SHA-256 run 2: " + digest_b)

import hashlib
import json
import math
import random

title = 'Delia Online'
entries = 2000
categories = ['Cakes', 'Mains', 'Starters', 'Desserts', 'Baking']
trials = 25
seed = 28
claimed_note = "Published holdings: about 2,000 recipes from Delia Smith's books and series; the demo samples 25 entries by course and does not query the live database."

def run_once():
    rng = random.Random(seed)
    counts = {c: 0 for c in categories}
    for _ in range(trials):
        counts[rng.choice(categories)] += 1
    return counts

expected = trials / len(categories)
counts_a = run_once()
counts_b = run_once()
chi2 = sum((o - expected) ** 2 / expected for o in counts_a.values())

          "counts": counts_a, "chi_square": round(chi2, 3)}

import random
