  1. A Profile for Larger Text

    Record 1 of 24. simple. Feasibility: buildable-now. The design uses only web pages, forms, and counters that exist today; only the design work stands in the way.

    The universal accessibility interface adapting to individual needs fits a page to the person reading it: larger text, stronger contrast, a slower reading pace, fewer words at once, or keys alone. Every profile is a design study, and the guide never claims a profile fits a real person it has never met. A profile that makes text larger and keeps the lines readable. The design for this record must state the idea in plain sentences, name what a visitor does first, and say what good looks like when it works, so a reader can judge the design without building anything. Without that plain statement, the idea stays vague, a visitor cannot tell what the design promises, and a promising idea is lost because nobody could explain it in words a newcomer can follow. A reader who can follow the design in words can also check it, and a design that can be checked is a design worth building. Worked example, Signature design: the same access profile is rebuilt from the Signature pattern, so a profile for larger text runs as a small, complete feature a visitor can try in one sitting, with the fair-play and moderation rules of this database applied throughout.

    History: Fitting a thing to the person who uses it is an old habit: a chair raised for a short reader, a lamp moved for tired eyes, a book held closer. The website form grows out of that habit, adding a profile that fits the page to the reader. A Profile for Larger Text grows out of an older habit: fitting a chair, a lamp, and a book to the reader, not the reader to them, and the website form adds a plain list, a search, and a written record for it.

    Proposed solution: Sketch the Signature access profile first, then write the rules from the sketch; State the fair-play rule the design must keep, in one sentence; Build the access profile from the Signature pattern: public spaces only, no private messages; Let a visitor try one Signature access profile without signing in; Check the Signature access profile on a phone and on a computer before publishing.

    Dependencies: What must exist first: plain questions about how a person reads best, a profile for each answer, a written reason for each setting, and a review step before publishing. Nothing else is needed to open the first access profile.

    Verification path: A visitor opens one access profile, follows the rules in plain sentences, and finishes it without help. The demo program prints the same total as the math proof, and a second visitor repeating the steps gets the same result.
