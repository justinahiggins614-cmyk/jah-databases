DBpedia: what it is, and the scope of what it covers.

DBpedia is a Linked Data publisher that extracts structured content from Wikipedia: every article becomes a resource with typed properties, labels, abstracts, and links to other datasets. It is the Linked Data version of Wikipedia. Structured facts from Wikipedia, in up to 111 language editions, as RDF triples. This record exists because a newcomer to DBpedia needs one plain answer before anything else: what is this source, and what does it cover? With it, the rest of the guide falls into place, because each later record builds on this definition. The scope note matters as much as the definition: knowing what DBpedia does not cover prevents the most common wasted afternoon in this work, which is searching a source for data it never held.

Science proof

DBpedia is a directed labeled multigraph like Wikidata, but its edges are extracted, not authored: infobox fields become triples. Graph theory gives the working rules: a resource's degree is the number of triples that mention it; a query is a pattern match over that graph; and the link structure (owl:sameAs, dbo:wikiPageWikiLink) is a small-world network, so two hops from a famous resource reaches an enormous neighbourhood. That is why DBpedia queries must be anchored on a named resource and limited early: an unanchored two-hop pattern explodes combinatorially. For this aspect (What It Is and Its Scope), the same graph theory rules decide what counts as a correct answer: the pattern must match the model, and the result must be checkable against the source.

DBpedia: every public way in, in one place.

DBpedia: the identifier scheme, and how to read an ID.

Every record in DBpedia has an identifier, and the identifier is the only handle that never changes with the record's content. The scheme is: Every resource is http://dbpedia.org/resource/<Name>, where <Name> is taken from the URL of the source English Wikipedia article (http://en.wikipedia.org/wiki/<Name>). Classes and properties live under http://dbpedia.org/ontology/ (dbo:) and raw infobox properties under http://dbpedia.org/property/ (dbp:). Language editions use their own subdomains. A reader who understands the scheme can read an ID and know what it names, which collection it belongs to, and how to fetch it. A reader who does not will confuse two records with similar names, cite the wrong one, or store a name where an ID belongs and watch the link break when the name changes. The rule is absolute: store the ID, display the name, and never use the name as the key.
