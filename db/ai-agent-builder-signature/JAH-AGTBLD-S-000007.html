AI Agent Builder: Signature Data Model

The Signature data model extends the public model with Signature fields: the same eight fields, plus the design-study markers that say what is Signature-made, what it was built from, and which generator produced it. Storage is the same small file-based database or JSONL files, so Signature data stays readable without special tools. This record lists the Signature fields and what each one means. In this Signature edition the program offers 8 capabilities (creating a specialist agent from a name and duties (1); plain-words instructions the agent follows (2); tools the agent may use, named one by one (3); a test for every duty (4); registration in the AI Phone Book with lineage (5); agents that talk like a human and explain their duties (6); an API other programs use to build agents (7); a plain-text build report (8)), 6 interfaces (Agent form — name and duties, in plain words; Duty list — each duty with the tool it uses; Instruction view — the plain-words instructions, readable and editable; Test run — run the duty tests and see the result; Builder API — machine-readable agent building for other programs; Plain-text mode — the build report as readable plain text), and 8 data fields (name — the agent's name; duties — the duties it performs; instructions — its plain-words instructions; tools — the tools it may use; tests — the test result for every duty; phone_book — its registration in the AI Phone Book; lineage — what it was built from; version — its version number). This record is number 7 of 24 in the Signature edition of the AI Agent Builder database pair, and it specifies the signature data model topic in full — what it is, how it works, what it accepts, what it returns, and how it is tested — so that a builder can build it and a tester can verify it without guessing.
