An Individual File Manifest is the manifest for one file: the file's name, its place in its database, its format, and the records it holds. Every file in the network has its own manifest entry, so a reader can ask what one file contains without opening the whole database. The live substance is the file indexes themselves: the JSON and JSONL index files the network publishes, such as the equation, patent, spec, word, wiki, and book indexes listed in the live access file.

Individual file manifests were needed once databases grew past a single index file and a reader had to know which file held which records. The manifest gives each file its own entry, naming the file and what it holds. This record does not state a creation date.

An individual file manifest works by holding one entry per file with the file's name, its database, its format, and the records it holds, so a lookup for one file returns exactly that file's facts. The entry is read from the file itself, so the manifest can never describe a file that does not exist. A file that moves gets a corrected entry, and a file that is removed is reported as gone, not left in the list.
