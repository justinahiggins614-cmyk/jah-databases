Knowledge Graph Explorer: Main Screen: the Human Interface

JAH-KGE-000004 — knowledge graph explorer record

The main screen is the human face of the Knowledge Graph Explorer: one page that shows the program's name, its purpose in plain words, and its main action, with every button doing what it says. A first-time user must be able to complete the program's main job from this screen without reading documentation first. This record specifies the screen's parts, the order they appear in, and what each control does when used — including what happens when the user makes a mistake. In this public edition the program offers 8 capabilities (walking from one concept to a related concept (1); showing the path taken, link by link (2); listing every neighbour of a concept (3); finding the shortest path between two concepts (4); filtering links by kind (depends on, records, belongs to) (5); a plain-text path readable without JavaScript (6); an API other programs use to walk the graph (7); links back to the records each concept came from (8)), 6 interfaces (Concept search — find a concept by name; Neighbour list — everything directly linked to the open concept; Path view — the links from one concept to another, step by step; Graph map — a readable map of a concept and its neighbours; Explorer API — machine-readable graph walking for other programs; Plain-text mode — any path as readable plain text), and 8 data fields (concept — the starting concept; neighbours — the concepts directly linked to it; path — the links from one concept to another; link_kind — what kind of link each step is; source_record — the record each concept came from; distance — how many links the path uses; filtered — the link kinds the walk was limited to; walk_date — the date the graph was read). This record is number 4 of 24 in the public edition of the Knowledge Graph Explorer database pair, and it specifies the main screen: the human interface topic in full — what it is, how it works, what it accepts, what it returns, and how it is tested — so that a builder can build it and a tester can verify it without guessing.
