A design for a multiplayer drawing game that keeps a library of fair prompts, so a host can pick a prompt that has already been checked instead of choosing a new one. This is a design for a website that has not been built yet, not a real product.

Choosing every prompt from scratch is slow, and choosing in a hurry makes mistakes: a word that cannot be drawn, a word that is too hard, or a word that is unfair, and the players find out before the host does. A library that keeps prompts already checked for fairness, lets the host pick one with a click, and shows the reason beside each prompt, removes the risk: the host picks a checked prompt, the players draw it, and the prompt is fair. The library covers the subjects drawing games actually ask, each prompt checked once and reused, and the host never has to trust an unchecked prompt.

Worked example: a host picks cat from the library, plays it, and the prompt is fair, with the reason shown beside it.

A field guide index to the twenty-three records in this database: a map of the whole set, ordered simple to compounded to complex, so a reader can find any record by number and by name. This is a design index for a website that has not been built yet, not a real product.

This database holds twenty-three full records about the multiplayer drawing game, ordered from simple to compounded to complex, and a reader arriving without a map cannot tell which record to read first, which records belong together, or where the harder designs begin. The field guide index solves that by listing every record by number and by name, in order, with a one-line account of what each record covers and which rung of the ladder it sits on. Without the index, the simple records and the complex records blur together, and a reader who needs the basics may open a complex design first, while a reader who wants the hardest designs may never find them. The index is the map that keeps the ladder readable, and it is the record that turns twenty-three separate designs into one set a reader can walk through from start to finish.

History

Field guide indexes descend from the tables of contents of books and the catalogues of libraries, where a list of what a collection holds came first and the collection itself came second; this index is the same old habit, written for a database of designs.

Proposed solution

List every record by number, in ladder order; Give each record a one-line account of what it covers; Mark each record simple, compounded, or complex; Point simple readers to records 1 to 8, and advanced readers to records 17 to 23; Keep the index beside the records, never apart from them.

Dependencies

The twenty-three records themselves, listed in order; the ladder ranks simple, compounded, and complex; agreement that an index lists, and never replaces, the records it points to.

Feasibility

buildable-now — An index is a list with one-line accounts, written with tools that exist today; only care in listing stands in the way.
