The Code Debugger Database (Signature)

Accessible version: plain text, no scripts, no sign-in, free forever. A code debugger runs code step by step and shows what changes: watch a variable, stop at a breakpoint, read the error line, and find the bug. The local debugger on this page steps through a small program in this browser, with no connection. Nothing is uploaded anywhere.

Twenty-four full records, ordered simple to working to advanced.

  1. What a Debugger Does

    Record 1 of 24. simple. Feasibility: buildable-now. A debugger runs code step by step and shows what changes at each step. Stepping through 4 lines shows 4 steps

    Math proof: Debugging is counting steps: stepping through 4 lines shows 4 steps, and a breakpoint on line 3 stops the run at line 3 of 5. Watching x shows 1, then 2, then 3. A loop meant to run 3 times that runs 4 times is 1 too many. 2 + 3 is 5, but 2 - 3 is -1: the wrong operator changes the answer by 6. A bug that appears 1 time in 10 runs needs 10 runs to catch.

    Science proof: A debugger works because a program is a list of steps, and each step changes the state by a known amount: watching the state at each step shows exactly where it first goes wrong. A breakpoint freezes the state at one line, and a stack trace lists the calls that led there. That is why the debugger shows the steps instead of only the final answer: the wrong step is the bug.
