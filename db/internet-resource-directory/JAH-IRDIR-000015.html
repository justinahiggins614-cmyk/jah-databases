Internet Resource Directory: Integration with the Other 99 Programs

JAH-IRDIR-000015 — internet resource directory record

The Internet Resource Directory works with the other ninety-nine programs in the 100: it offers its own job through its API, and it uses the other programs' APIs where they do a job better — search through the Universal Search Engine, storage through the Database Builder, verification through the Software Testing Center. This record names the programs it depends on, the programs that depend on it, and the order they are built in, so that no program is built before the programs it needs. In this public edition the program offers 8 capabilities (a catalog entry for every useful website and service (1); keyword search across names and descriptions (2); subject browsing from general to specific (3); live checks that mark dead addresses unreachable (4); a submission queue for new resources with review (5); plain-text directory readable without JavaScript (6); an API other programs use to look up resources (7); links to the full site, never a copy of it (8)), 6 interfaces (Directory browse — subjects listed from general to specific, collapsible by letter; Search box — keyword search across names, descriptions, and subjects; Entry page — name, address, description, subjects, and last check date; Submit form — propose a new resource for review; Directory API — machine-readable lookup for other programs; Plain-text mode — the whole directory as readable plain text), and 8 data fields (name — the resource's official name; address — its web address, checked live; description — what it does, in plain words; subjects — the subjects it covers; checked — the date its address was last checked; status — live or unreachable, with reason; submitted_by — who proposed it, for review only; review — the review decision and date). This record is number 15 of 24 in the public edition of the Internet Resource Directory database pair, and it specifies the integration with the other 99 programs topic in full — what it is, how it works, what it accepts, what it returns, and how it is tested — so that a builder can build it and a tester can verify it without guessing.
