Internet Resource Directory: Command Line and Batch Use

JAH-IRDIR-000006 — internet resource directory record

The Internet Resource Directory also works from the command line and in batches: the same job the screen does can be run without a screen, one item at a time or many at once, so that repeated work can be scripted and scheduled. Batch runs read their input from a file, write their results to a file, and report a summary line for every item — passed, failed, or held — so that a run of a thousand items is as checkable as a run of one. This record specifies the commands, their inputs, and their outputs. In this public edition the program offers 8 capabilities (a catalog entry for every useful website and service (1); keyword search across names and descriptions (2); subject browsing from general to specific (3); live checks that mark dead addresses unreachable (4); a submission queue for new resources with review (5); plain-text directory readable without JavaScript (6); an API other programs use to look up resources (7); links to the full site, never a copy of it (8)), 6 interfaces (Directory browse — subjects listed from general to specific, collapsible by letter; Search box — keyword search across names, descriptions, and subjects; Entry page — name, address, description, subjects, and last check date; Submit form — propose a new resource for review; Directory API — machine-readable lookup for other programs; Plain-text mode — the whole directory as readable plain text), and 8 data fields (name — the resource's official name; address — its web address, checked live; description — what it does, in plain words; subjects — the subjects it covers; checked — the date its address was last checked; status — live or unreachable, with reason; submitted_by — who proposed it, for review only; review — the review decision and date). This record is number 6 of 24 in the public edition of the Internet Resource Directory database pair, and it specifies the command line and batch use topic in full — what it is, how it works, what it accepts, what it returns, and how it is tested — so that a builder can build it and a tester can verify it without guessing.
