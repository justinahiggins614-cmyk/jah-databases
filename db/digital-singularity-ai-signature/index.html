Description

This design-study record designs a Signature sandbox: a room for generated code with four walls, the filesystem wall, the network wall, the time wall, and the privilege wall. Inside the room, generated code can build and run. Outside the room, the host, the trusted runtime, and the user's data sit untouched. The Problem

Generated code cannot be trusted, and a subprocess boundary is too thin to contain it: it shares the host's filesystem, its network, its time, and its privileges. The design problem is containment with named walls: each wall must be a real isolation mechanism, not a policy, so that a generated program that tries to escape meets a wall rather than a suggestion.

The Worked Solution

The filesystem wall gives the room its own files and no access to the host's. The network wall gives the room no network unless the task explicitly authorizes one, and then only the authorized destination. The time wall kills any run past its timeout. The privilege wall runs the room as an unprivileged user with no access to the trusted runtime. The room is created fresh per run, its outputs are copied out through a checked channel, and the room is destroyed afterward. The demo recomputes the checkable part of this solution from the key figures {"sandbox_walls": 4, "safe_states": 1, "wall_states": 16, "security_controls": 11}.
