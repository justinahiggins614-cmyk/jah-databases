Universal Construction Center: Core Capabilities

JAH-CONSTC-000003 — universal construction center record

The Universal Construction Center offers eight core capabilities, and this record names all eight, what each one does, and how they fit together. No capability stands alone: each one feeds the next, so that a request moves from the user's words to a checked, recorded result without a gap. A capability that cannot be tested is not a capability — it is a wish — so each of the eight carries its own acceptance check, listed in this record and executed by the program's test suite. In this public edition the program offers 8 capabilities (planning a build from dependencies and acceptance tests (1); running the build through the builder programs (2); running the tests through the Software Testing Center (3); writing the build report with evidence (4); showing the status of every program in the 100 (5); holding what is not yet verified, never claiming it built (6); an API other programs use to plan and report builds (7); a plain-text status report (8)), 6 interfaces (Build plan — dependencies, order, and acceptance tests for a program; Status board — every program in the 100 with its state: planned, building, tested, held; Run button — plan, build, test, and report one program; Build report — what was built, what passed, what failed, what is held; Center API — machine-readable build planning for other programs; Plain-text mode — the status report as readable plain text), and 8 data fields (program — the program being built; plan — its dependencies, order, and acceptance tests; build_result — what the builders produced; test_result — what the Testing Center recorded; report — the build report with evidence; status — planned, building, tested, or held; held — what is held and why; run_date — the date the build ran). This record is number 3 of 24 in the public edition of the Universal Construction Center database pair, and it specifies the core capabilities topic in full — what it is, how it works, what it accepts, what it returns, and how it is tested — so that a builder can build it and a tester can verify it without guessing.
