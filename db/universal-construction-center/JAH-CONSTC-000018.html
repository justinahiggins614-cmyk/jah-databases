Universal Construction Center: Accessibility and Plain-Text Version

JAH-CONSTC-000018 — universal construction center record

The Universal Construction Center is usable by everyone, including people and programs that cannot run JavaScript: every page has a plain, readable version with the same content, the same actions described in words, and no step that requires a script. Text is plain, buttons are labeled with what they do, and nothing essential hides behind a picture. This record specifies the accessible version of every page and the check that proves each one matches the full version. In this public edition the program offers 8 capabilities (planning a build from dependencies and acceptance tests (1); running the build through the builder programs (2); running the tests through the Software Testing Center (3); writing the build report with evidence (4); showing the status of every program in the 100 (5); holding what is not yet verified, never claiming it built (6); an API other programs use to plan and report builds (7); a plain-text status report (8)), 6 interfaces (Build plan — dependencies, order, and acceptance tests for a program; Status board — every program in the 100 with its state: planned, building, tested, held; Run button — plan, build, test, and report one program; Build report — what was built, what passed, what failed, what is held; Center API — machine-readable build planning for other programs; Plain-text mode — the status report as readable plain text), and 8 data fields (program — the program being built; plan — its dependencies, order, and acceptance tests; build_result — what the builders produced; test_result — what the Testing Center recorded; report — the build report with evidence; status — planned, building, tested, or held; held — what is held and why; run_date — the date the build ran). This record is number 18 of 24 in the public edition of the Universal Construction Center database pair, and it specifies the accessibility and plain-text version topic in full — what it is, how it works, what it accepts, what it returns, and how it is tested — so that a builder can build it and a tester can verify it without guessing.
