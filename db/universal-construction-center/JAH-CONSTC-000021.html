Universal Construction Center: Failure Modes and Recovery

JAH-CONSTC-000021 — universal construction center record

The Universal Construction Center fails safely: this record names the ways it can fail — a missing file, a refused input, an unreachable source, a test that does not pass — and what the program does in each case. A failure never loses data, never writes a half-result, and never pretends to have succeeded. Each failure mode carries its recovery: what the user does, what the program does on its own, and how to tell the failure is fixed. In this public edition the program offers 8 capabilities (planning a build from dependencies and acceptance tests (1); running the build through the builder programs (2); running the tests through the Software Testing Center (3); writing the build report with evidence (4); showing the status of every program in the 100 (5); holding what is not yet verified, never claiming it built (6); an API other programs use to plan and report builds (7); a plain-text status report (8)), 6 interfaces (Build plan — dependencies, order, and acceptance tests for a program; Status board — every program in the 100 with its state: planned, building, tested, held; Run button — plan, build, test, and report one program; Build report — what was built, what passed, what failed, what is held; Center API — machine-readable build planning for other programs; Plain-text mode — the status report as readable plain text), and 8 data fields (program — the program being built; plan — its dependencies, order, and acceptance tests; build_result — what the builders produced; test_result — what the Testing Center recorded; report — the build report with evidence; status — planned, building, tested, or held; held — what is held and why; run_date — the date the build ran). This record is number 21 of 24 in the public edition of the Universal Construction Center database pair, and it specifies the failure modes and recovery topic in full — what it is, how it works, what it accepts, what it returns, and how it is tested — so that a builder can build it and a tester can verify it without guessing.
