API Builder: Testing Strategy and Test Suite

JAH-APIB-000016 — api builder record

The API Builder is tested by a suite that runs by execution: every capability has a test, every interface call has a test, and every test names what it proves. The suite runs in isolation — one failing test cannot hide another — and the verdict is pass only when failures are zero. This record lists the tests, what each one checks, and the evidence each one produces, so that anyone can re-run the suite and reach the same verdict. In this public edition the program offers 8 capabilities (creating an interface contract from a list of resources (1); generating working server code for the contract (2); documentation for every endpoint (3); a test for every endpoint (4); validation that rejects malformed calls with a clear error (5); versioning so old clients keep working (6); an API other programs use to build APIs (7); a plain-text build report (8)), 6 interfaces (Resource form — resources and their fields, in plain words; Endpoint list — every call the interface offers, with its inputs and outputs; Contract view — the machine-readable contract, readable and downloadable; Test run — run the endpoint tests and see the result; Builder API — machine-readable API building for other programs; Plain-text mode — the build report as readable plain text), and 8 data fields (resources — the things the system holds; endpoints — the calls the interface offers; contract — the machine-readable OpenAPI specification; server_code — the working server code; documentation — what each endpoint does, in plain words; tests — the test result for every endpoint; version — the contract version; errors — how malformed calls are answered). This record is number 16 of 24 in the public edition of the API Builder database pair, and it specifies the testing strategy and test suite topic in full — what it is, how it works, what it accepts, what it returns, and how it is tested — so that a builder can build it and a tester can verify it without guessing.
