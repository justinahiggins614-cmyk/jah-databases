API Builder: Application Programming Interface (API)

JAH-APIB-000005 — api builder record

The Application Programming Interface (API) is the machine-readable contract of the API Builder: the set of calls another program may make, what each call needs, and what it returns. Every call is named, its inputs are listed with their types, and its outputs are listed with their shapes, so that a program written against this contract works the first time. A malformed call is answered with a clear error that names the problem, never with silence and never with a crash. In this public edition the program offers 8 capabilities (creating an interface contract from a list of resources (1); generating working server code for the contract (2); documentation for every endpoint (3); a test for every endpoint (4); validation that rejects malformed calls with a clear error (5); versioning so old clients keep working (6); an API other programs use to build APIs (7); a plain-text build report (8)), 6 interfaces (Resource form — resources and their fields, in plain words; Endpoint list — every call the interface offers, with its inputs and outputs; Contract view — the machine-readable contract, readable and downloadable; Test run — run the endpoint tests and see the result; Builder API — machine-readable API building for other programs; Plain-text mode — the build report as readable plain text), and 8 data fields (resources — the things the system holds; endpoints — the calls the interface offers; contract — the machine-readable OpenAPI specification; server_code — the working server code; documentation — what each endpoint does, in plain words; tests — the test result for every endpoint; version — the contract version; errors — how malformed calls are answered). This record is number 5 of 24 in the public edition of the API Builder database pair, and it specifies the application programming interface (api) topic in full — what it is, how it works, what it accepts, what it returns, and how it is tested — so that a builder can build it and a tester can verify it without guessing.
