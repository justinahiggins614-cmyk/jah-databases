    The guess-the-song game plays a short piece of a tune and asks the player to name the song, in plain words, before more of the tune is played. A song guessing round plays only a short clip of a tune, because the whole song would give the answer away and no clip at all would leave nothing to guess.     Proposed solution: Add a tournament bracket with rounds, divisions, and a season; Add a creator studio so visitors can build a new song round; Add a review step so every new song round is checked before it is published; Add the song round in many languages, with the same rules in each; Add an offline pack so the song round works with no connection.

    Dependencies: What must exist first: a tune library, a clip player that plays short pieces, a hint system, and a score counter. A tournament system, a creator studio, a review step, translations, and an offline pack are also needed before the complex song rounds open.

    Verification path: A tournament runs a full season, a creator publishes a new song round through the review step, and the offline pack is tried with no connection. The demo program prints the same total as the math proof, and every step is checked by a second reader.

    Science proof: total = count x each. In plain words, this equation turns counted quantities into one checkable number: with 23 items at 1 each, the arithmetic gives 23 records, and the demo prints that same total, so the claim can be checked by arithmetic alone.

    Math proof: Worked arithmetic: 23 x 1 = 23. The demo sets count to 23 and each to 1, multiplies them, and prints Total: 23, so a fresh run of the demo verifies this proof exactly.
