Internet Resource Directory: Signature Batch and Offline Use

JAH-IRDIR-S-000006 — internet resource directory record

The Signature edition of the Internet Resource Directory works offline first: its batch commands run without a network, read input from a file, and write results to a file, so that Signature work continues where there is no connection. A batch run reports a summary line for every item — passed, failed, or held. This record specifies the Signature batch commands, their inputs, and their outputs, as a design for offline-first Signature work. In this Signature edition the program offers 8 capabilities (a catalog entry for every useful website and service (1); keyword search across names and descriptions (2); subject browsing from general to specific (3); live checks that mark dead addresses unreachable (4); a submission queue for new resources with review (5); plain-text directory readable without JavaScript (6); an API other programs use to look up resources (7); links to the full site, never a copy of it (8)), 6 interfaces (Directory browse — subjects listed from general to specific, collapsible by letter; Search box — keyword search across names, descriptions, and subjects; Entry page — name, address, description, subjects, and last check date; Submit form — propose a new resource for review; Directory API — machine-readable lookup for other programs; Plain-text mode — the whole directory as readable plain text), and 8 data fields (name — the resource's official name; address — its web address, checked live; description — what it does, in plain words; subjects — the subjects it covers; checked — the date its address was last checked; status — live or unreachable, with reason; submitted_by — who proposed it, for review only; review — the review decision and date). This record is number 6 of 24 in the Signature edition of the Internet Resource Directory database pair, and it specifies the signature batch and offline use topic in full — what it is, how it works, what it accepts, what it returns, and how it is tested — so that a builder can build it and a tester can verify it without guessing.
