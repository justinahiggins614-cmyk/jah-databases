Internet Resource Directory: Signature Overview: What the Signature Edition Adds

JAH-IRDIR-S-000001 — internet resource directory record

The Signature edition of the Internet Resource Directory is the network's own design of the program: the same job as the public edition, built as original Signature work with its own interface, its own data model, and its own generator. It is a design-study — an original design, presented as a design, never as an established fact or a real public record. This record states what the Signature edition adds, what it deliberately leaves out, and where its designs came from. In this Signature edition the program offers 8 capabilities (a catalog entry for every useful website and service (1); keyword search across names and descriptions (2); subject browsing from general to specific (3); live checks that mark dead addresses unreachable (4); a submission queue for new resources with review (5); plain-text directory readable without JavaScript (6); an API other programs use to look up resources (7); links to the full site, never a copy of it (8)), 6 interfaces (Directory browse — subjects listed from general to specific, collapsible by letter; Search box — keyword search across names, descriptions, and subjects; Entry page — name, address, description, subjects, and last check date; Submit form — propose a new resource for review; Directory API — machine-readable lookup for other programs; Plain-text mode — the whole directory as readable plain text), and 8 data fields (name — the resource's official name; address — its web address, checked live; description — what it does, in plain words; subjects — the subjects it covers; checked — the date its address was last checked; status — live or unreachable, with reason; submitted_by — who proposed it, for review only; review — the review decision and date). This record is number 1 of 24 in the Signature edition of the Internet Resource Directory database pair, and it specifies the signature overview: what the signature edition adds topic in full — what it is, how it works, what it accepts, what it returns, and how it is tested — so that a builder can build it and a tester can verify it without guessing.
