Overview

The Signature Periodic Table Service Database holds 24 full periodic table service record records, in a teaching ladder: 8 simple, 8 compounded, 8 most complex. This edition is the Signature edition. It expands the live database periodic-elements, which holds 118 records; this pair links to it and never rebuilds it. This database carries the specification, models, test suites and verification records; it is not a running service.

Generator ceiling: up to 1,000,000,000 scales per file, generated on demand by the file AI — not stored files.

The Design/System

The design is one database per subject, with a public edition and a Signature edition side by side. Every record gives its history, its full content, its methods, its results as reported, and its skeptical analysis. Every technical term is defined in plain words where it first appears, and the glossary defines them all again. Each Signature record is a design study, labeled as a design, never presented as established fact.

The Generator

The boundless generator for this database is the file gen-periodic-table-service-signature.js. It is seeded and deterministic: the same seed always gives the same record, and different seeds differ. It is throttled to 100 records per call, it stops at 1,000,000,000 records per file, and every generated record is labeled generated, never presented as an archive record.

Its full specification is downloadable: periodic-table-service-signature-ai.json.

Math Proof

The counting argument is exact: 24 records, 8 simple, 8 compounded, 8 most complex, and 8 + 8 + 8 = 24. The formal statement is: element(Z) = the element with atomic number Z, one proton per unit of Z (stated, not machine-checked) The scientific statement is: period = the row holding elements whose outer shell fills in order; group = the column sharing outer-shell count (stated, not machine-checked) Both are stated, not machine-checked, and the record-level proofs are in each record's math proof.

The scientific claim is that the subject can be stated, built, and checked by the method in the records: state it in plain words, define every term, run the demo and the program as real programs, and re-verify independently. The check is the validator and the independent CHECK 2, both of which re-run every demo and program.
