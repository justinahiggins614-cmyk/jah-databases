Documentation Generator: Import: Bringing Data In

JAH-DOCGEN-000012 — documentation generator record

The Documentation Generator brings data in from outside: it reads files in the formats its users already have, checks each incoming record against the same validation rules as typed input, and reports exactly what was accepted, what was refused, and why. An import never overwrites existing data without saying so, and a failed import leaves the program exactly as it was. This record specifies the accepted formats, the checks each record passes through, and the report every import produces. In this public edition the program offers 8 capabilities (generating full documentation from code and a specification (1); defining every technical term on first use (2); documenting every interface with inputs and outputs (3); listing every test with what it proves (4); a glossary of every term the document uses (5); plain-text documentation readable without JavaScript (6); an API other programs use to generate documentation (7); re-generating docs when the program changes (8)), 6 interfaces (Document form — program name, purpose, interfaces, and tests; Section list — every section the document will hold; Document view — the full document, readable and downloadable; Glossary view — every term defined in plain words; Generator API — machine-readable documentation generation for other programs; Plain-text mode — the document as readable plain text), and 8 data fields (program — the program documented; purpose — its purpose in plain words; interfaces — every interface with inputs and outputs; terms — every technical term defined; tests — every test with what it proves; glossary — the glossary of terms used; generated_date — the date the document was generated; version — the program version documented). This record is number 12 of 24 in the public edition of the Documentation Generator database pair, and it specifies the import: bringing data in topic in full — what it is, how it works, what it accepts, what it returns, and how it is tested — so that a builder can build it and a tester can verify it without guessing.
