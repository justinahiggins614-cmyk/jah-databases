Workflow Automation: Testing Strategy and Test Suite

JAH-WFA-000016 — workflow automation record

The Workflow Automation is tested by a suite that runs by execution: every capability has a test, every interface call has a test, and every test names what it proves. The suite runs in isolation — one failing test cannot hide another — and the verdict is pass only when failures are zero. This record lists the tests, what each one checks, and the evidence each one produces, so that anyone can re-run the suite and reach the same verdict. In this public edition the program offers 8 capabilities (running a list of steps in order (1); passing each step's result to the next step (2); recording every step's outcome with its evidence (3); stopping clearly at the first failing step (4); re-running a workflow from any step (5); a plain-text run report readable without JavaScript (6); an API other programs use to run workflows (7); approval gates on steps that change anything (8)), 6 interfaces (Workflow form — steps listed in order, in plain words; Step list — each step with its action and inputs; Run button — execute the workflow and watch each step report; Run report — every step with its result and evidence; Automation API — machine-readable workflow running for other programs; Plain-text mode — the run report as readable plain text), and 8 data fields (steps — the steps in order; results — each step's result; failed_step — the first step that failed, if any; evidence — what each step proved; approvals — the approvals given for steps that change things; run_date — the date the workflow ran; duration — how long the run took; verdict — pass only when every step passed). This record is number 16 of 24 in the public edition of the Workflow Automation database pair, and it specifies the testing strategy and test suite topic in full — what it is, how it works, what it accepts, what it returns, and how it is tested — so that a builder can build it and a tester can verify it without guessing.
