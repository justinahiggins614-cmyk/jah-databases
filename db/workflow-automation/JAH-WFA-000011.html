Workflow Automation: Logging and Audit Trail

JAH-WFA-000011 — workflow automation record

The Workflow Automation keeps a log: every important action is written down with its date, who or what did it, what went in, and what came out, so that any result can be traced back to its cause. The log is append-only — entries are added, never rewritten — and it is readable as plain text. This record specifies what is logged, what is never logged (keys, secrets, and personal data are never written to a log), and how long entries are kept. In this public edition the program offers 8 capabilities (running a list of steps in order (1); passing each step's result to the next step (2); recording every step's outcome with its evidence (3); stopping clearly at the first failing step (4); re-running a workflow from any step (5); a plain-text run report readable without JavaScript (6); an API other programs use to run workflows (7); approval gates on steps that change anything (8)), 6 interfaces (Workflow form — steps listed in order, in plain words; Step list — each step with its action and inputs; Run button — execute the workflow and watch each step report; Run report — every step with its result and evidence; Automation API — machine-readable workflow running for other programs; Plain-text mode — the run report as readable plain text), and 8 data fields (steps — the steps in order; results — each step's result; failed_step — the first step that failed, if any; evidence — what each step proved; approvals — the approvals given for steps that change things; run_date — the date the workflow ran; duration — how long the run took; verdict — pass only when every step passed). This record is number 11 of 24 in the public edition of the Workflow Automation database pair, and it specifies the logging and audit trail topic in full — what it is, how it works, what it accepts, what it returns, and how it is tested — so that a builder can build it and a tester can verify it without guessing.
