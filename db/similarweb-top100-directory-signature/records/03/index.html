History

Social networks grew out of forums, which are message boards about one subject, and personal profile pages. Friend lists, photo sharing, and the endless scrolling feed turned them from places to visit into places to live in. Short video, stories that vanish after a day, and live video were added later, and the biggest networks now count their users in the billions.

Description

A social network is a service where a person keeps a profile, which is a page about themselves, follows other people, groups, and pages, and sees a feed, which is a running list of posts, pictures, short videos, and links chosen for them. People post their own updates, comment on others, share links, join groups about a shared interest, and send private messages. The feed is the centre of the service: it decides what each person sees, in what order, and how often. The Signature equivalent is the live Signature Social mirror: a local feed where a person can post a short message and see it beside the mirror's own sample posts, with no account, no tracking, and every post shown in the order it was made, so the reader, not the feed, decides what matters. The Problem

The problem this record solves is the same as its public sibling, stated in the network's own words: a person who wants to use the network well needs to know what kind of service social networks is, and whether the network already provides it. Without a Signature entry, the answer would have to borrow another service's name, which the standing trademark rule forbids. With this entry, the service is described by what it does, the live mirror is linked where one exists, and the gap is named as a design study where none exists yet.

The Worked Solution

The method is the same for every record in this pair, carried out in the network's own words. First, the public ranking was read and parsed into rank, site, and main use, giving 88 rows. Second, each site was assigned to exactly one of the twenty categories by what the service does. Third, each category was checked against the twelve live Tier 1 mirrors by exact match, and given a verdict: LINK, EXPAND, BUILD, or NOT BUILT for duplicates. Fourth, the numbers were recomputed by the demonstration program in this record, twice, and the two digests compared. No third-party brand name is used at any step of the Signature edition.

Limits

A feed shows what keeps a person scrolling, not what is most true or most important. Rumours spread fast, pictures can be edited or taken out of context, and the most extreme posts get the most attention. Time on a feed is easy to lose, and what a person sees is shaped by choices they never made. The ranking measures popularity, never quality, never truth, and never safety. The most-visited service in a category is not the best service, and a service that is missing from the ranking may be missing because it is used in an app, because it serves one country, or because it is new. This record claims only what its sources establish: the ranks, the counts, the verdict, and the mirror link. Everything else is labelled as design-study or as opinion, never as fact.

Science Proof

The science here is the science of measurement. A ranking that counts estimated browser visits is an estimate built from samples and models, not a direct count, and it carries error. Two facts follow. First, the order at the top is more reliable than the exact numbers: a service with far more visits than the next is almost certainly ahead, while two services close together could swap places if the measurement changed. Second, what is left out shapes the result as much as what is counted: phone-app activity is excluded, so services people mostly use in an app are under-counted, and twelve ranks are omitted from this directory, so the list has gaps. A reader who understands these two facts can use the ranking well; a reader who treats it as an exact count will be misled by it. estimated visits = sampled visits scaled by the model; the order is more reliable than the exact numbers

Terms in Plain Words

A database is a named collection of records about one subject, stored so a reader or a program can find, read, and check each record. A record is one entry in a database: a single file with all of its data, written so a person can read it and a program can run it. A slug is the short web-address name of a database, written in lower-case letters with hyphens, for example universal-knowledge. It is the name the database is filed under. The manifest is the master list of every database in the network, kept in data/manifest.json in the jah-databases repository. It records each database's slug, record kind, record count, identifier prefix, and AI name. A slug is free only if it is not already in the manifest. A record kind is the type name of a record, written as the database slug with spaces instead of hyphens. An identifier prefix is the short code stamped at the start of every record identifier in a database, for example JAH-SWTD-. It tells you which database a record belongs to. A generator is a program that creates new records or files on demand from a seed number. The same seed always produces the same output, so a generated record can be checked and reproduced. A seed is the starting number given to a generator. Change the seed and you get a different record; use the same seed and you get the same record again. A generator gate is a check that a generator must pass before its output counts: the emitted record must have the right record kind, the right slug, the database's own identifier prefix, the hard stop of 1,000,000,000, and the right generator prefix. A JCC code (JAH Condensed Code) is a short condensed key that points to one full record: JAHDB/<slug>#<id>, with a jcc_key of k= plus the first 8 characters of the SHA-256 digest of the record. A code is a pointer to the full data, never a replacement for it. An API (Application Programming Interface) is a set of rules that lets one program ask another program for data or work, over the web. MCP (Model Context Protocol) is an open standard that lets an AI program connect to outside tools and data sources through one shared set of rules. AI means artificial intelligence: a program that answers questions, explains, and does work, in plain words. A directory is a guide that lists services by what they do, so a reader can find the right kind of service. A category is one kind of service in a directory, for example search engines or shopping. A mirror is a Signature version of a kind of service, built on the network's own data, with its own name and catalogue. A ranking is a list in order, from most to least, by one measured thing. Estimated browser visits are a count of how many times pages were opened in a web browser, estimated from samples and models, not counted exactly, and not counting activity inside phone apps. The public edition is the edition of a database that records public facts with sources. The Signature edition is the edition made by the network itself, in its own words, with its own designs. A design-study is a design that is specified in full but not yet built or proved; it is never presented as an established fact. Public-harvest means the record was gathered from public records. Signature-generated means the record was made by the network as a Signature design. A teaching ladder is the order in which a database teaches: simple first, then compounded, then most complex. An accessible mirror is a version of a page that can be read without JavaScript, without an account, and by any visiting AI.
