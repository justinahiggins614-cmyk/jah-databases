Wikipedia: every public way in, in one place.

Wikipedia can be reached in several ways, and choosing the wrong one wastes time: a bulk question asked through a single-record API, or a single lookup attempted by downloading a multi-gigabyte dump. The access methods are: Read on the web at en.wikipedia.org; Wikimedia REST API at /api/rest_v1/ (summary, HTML, wikitext, metadata); MediaWiki REST API at /w/rest.php/v1/ (search, page history); MediaWiki Action API at /w/api.php; bulk dumps at dumps.wikimedia.org (XML, SQL, BitTorrent); Wikimedia Enterprise for high-volume and commercial use (free account, token). This record lays all of them out side by side with the rule for choosing between them, so a reader picks the right method before the first request. The rule is simple: one record, use the API; a narrow question, use the query endpoint; the whole corpus, use the dumps; and a live feed, use the stream if one exists.

Wikipedia: the rate limits, and how to stay a welcome guest.

Wikipedia is a shared public service, and its rate limits exist so one caller cannot crowd out the rest. The limits are: Limit clients to no more than 200 requests per second to the REST API overall; many entry points enforce more restrictive limits. Authenticated API requests receive higher rate limits. Always send a unique User-Agent. On HTTP 429, stop and respect Retry-After. This record exists because the most common way to lose access to a free service is to ignore its limits: a script that fires a thousand requests a second will be throttled, blocked, or served errors, and the failure will look like a bug in the script rather than a policy in the service. The fair-use rule is simple: keep requests modest, cache what you fetch, use the dumps for bulk work, and back off when the service says 429.

Wikipedia: the identifier scheme, and how to read an ID.

Every record in Wikipedia has an identifier, and the identifier is the only handle that never changes with the record's content. The scheme is: An article is identified by its title, which is unique within one language edition (Earth on English Wikipedia). The URL form is https://en.wikipedia.org/wiki/Earth; the API form is /api/rest_v1/page/summary/Earth. Every revision has a numeric revision id, and every page has a numeric page id that never changes even if the title is renamed. A reader who understands the scheme can read an ID and know what it names, which collection it belongs to, and how to fetch it. A reader who does not will confuse two records with similar names, cite the wrong one, or store a name where an ID belongs and watch the link break when the name changes. The rule is absolute: store the ID, display the name, and never use the name as the key.
